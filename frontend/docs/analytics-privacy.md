# Публичная статистика без доступа к интерфейсу аккаунта

`YandexMetrika` в корневом layout — невидимый контроллер жизненного цикла,
не Provider. Он создаёт один изолированный iframe только на разрешённых
публичных страницах production-доменов. На личных и неизвестных маршрутах
iframe удаляется; при прямом входе туда SDK вообще не загружается.

## Граница данных

`lib/analytics/yandexMetrika.ts` содержит список постоянных URL и заголовков.
Query, fragment, заголовок документа, имя человека и slug сообщества в него
не попадают. Публичные профили и сообщества объединяются в две категории.
Ссылка предыдущей страницы также берётся из этого списка. Авторизованный
посетитель может открывать публичную страницу; персональные окна этой
страницы остаются за границей iframe.

`/analytics/frame` — отдельный Route Handler с постоянным адресом, `no-store`
и `no-referrer`. Query отклоняется. И HTML-атрибут sandbox, и CSP ответа
разрешают скрипты без `allow-same-origin`: SDK не получает DOM родителя,
cookies или localStorage. Отдельный адрес нужен потому, что `srcdoc`
наследует base URL страницы и мог бы раскрыть query.

Родитель принимает ready только от текущего iframe с opaque origin `null`.
Iframe принимает сообщения только от своего родителя с точным разрешённым
production origin и повторно проверяет URL по постоянному списку. Свободные
params и переданный title игнорируются. CSP ограничивает сеть доменами
Метрики; создание дочерних iframe и отправка форм запрещены.

Webvisor, clickmap, ecommerce, trackLinks, trackHash, accurateTrackBounce,
sendTitle и YTM отключены. Одних этих флагов недостаточно: локальная проверка
официального SDK показала отправку ID формы при submit даже с отключённым
Webvisor. Поэтому SDK отделён от всего DOM приложения.

Это статистика агрегированных просмотров. Cookies/storage внутри iframe
недоступны: точность уникальных посетителей и атрибуции ограничена. SDK может
выдать SecurityError при попытке использовать такое хранилище. Бизнес-события,
воронка заказов и ecommerce здесь не реализованы. Внешний сервис всё ещё видит
сам сетевой запрос, включая IP; изоляция не означает анонимность транспорта.

## Проверка

```sh
npm run check
npx playwright install chromium
npm run check:analytics
# Дополнительный прогон сохранённого официального SDK:
npm run check:analytics -- --sdk /absolute/path/tag.js
```

Gate запускает настоящий production standalone Next и Chromium. Backend
заменён локальным anonymous fixture; запросы аналитики перехватываются,
синтетические посещения не отправляются в Метрику. Стандартный режим использует
агрессивный SDK fixture и работает независимо от доступности поставщика.
Он проверяет приватный вход, query/hash/Referer/title, форму и картинку с
синтетическим секретом, изоляцию DOM/cookies/storage, SPA-переход, один SDK
на публичные переходы и удаление iframe. Отказ загрузки service worker также
не должен давать необработанную ошибку приложения.

CI frontend job устанавливает Chromium и запускает этот gate после build.
Запуск GitHub Actions, текущие настройки серверного счётчика, реальные отчёты,
активация на публичном домене и внешние CDN-журналы этим не подтверждены.
