# Черновики конструктора

## Цель

Дать авторизованным пользователям возможность сохранять состояние конструктора,
видеть собственные черновики в панели `unfinished` и продолжать редактирование на
другом устройстве. Пользовательские изображения не должны попадать на сервер,
пока пользователь не сохранит черновик или не оформит созданный товар.

## Пользовательские сценарии

### Сохранение из конструктора

1. Пользователь нажимает `СОХРАНИТЬ` в popup выхода.
2. Если пользователь не авторизован, открывается существующий popup входа.
3. После успешной авторизации сохранение продолжается автоматически без
   повторного нажатия.
4. Локальные пользовательские изображения загружаются на сервер.
5. Создаётся новый черновик либо обновляется уже открытый черновик.
6. После успешного сохранения открывается панель `unfinished` с черновиками
   текущего пользователя.

При ошибке загрузки изображения или сохранения черновика конструктор остаётся
открытым, локальное состояние не теряется, а пользователь видит сообщение об
ошибке и может повторить сохранение.

### Продолжение редактирования

1. Панель `unfinished` получает список черновиков авторизованного пользователя.
2. Кнопка `Продолжить` открывает `/constructor?draftId=<id>`.
3. Конструктор загружает черновик, затем связанный товар и восстанавливает
   выбранный размер, сторону модели, украшения, координаты, масштаб и поворот.
4. Следующее сохранение обновляет этот же черновик и не создаёт копию.

### Удаление черновика

Удаление доступно только владельцу. После удаления черновик исчезает из панели,
а сервер удаляет пользовательские изображения, которые больше не используются
другими черновиками или покупками.

### Покупка без предварительного сохранения

При переходе от конструктора к покупке локальные пользовательские изображения
загружаются тем же механизмом. Идентификаторы изображений передаются вместе с
конфигурацией созданного товара. После подтверждения покупки сервер помечает
изображения как связанные с покупкой и не удаляет их вместе с черновиком.

## Архитектура

### Временное локальное хранение

Пользовательские изображения первоначально сохраняются как `Blob` в
`IndexedDB`. В состоянии конструктора используется локальный идентификатор и
object URL для отображения.

Каждая локальная запись содержит:

- локальный идентификатор;
- `Blob`, MIME-тип и исходное имя;
- размеры изображения;
- время создания и время последнего использования.

Записи старше 24 часов удаляются при запуске конструктора и при добавлении новых
изображений. Закрытие или обновление страницы не должно немедленно уничтожать
локальные изображения.

### Серверные изображения

Новый авторизованный endpoint загрузки принимает только поддерживаемые типы
изображений, проверяет размер файла и создаёт запись пользовательского медиа.
Ответ содержит стабильные `mediaId` и `url`.

Медиа имеет владельца и состояние:

- `pending`: файл загружен, но сохранение черновика ещё не завершилось;
- `draft`: файл используется хотя бы одним черновиком;
- `purchased`: файл связан с оформленным товаром.

Сохранение черновика передаёт список `mediaId`, и сервер проверяет, что все они
принадлежат текущему пользователю. Непривязанные `pending`-файлы старше одного
часа удаляются очисткой. При удалении или обновлении черновика сервер удаляет
медиа, которое больше нигде не используется и не имеет состояния `purchased`.

### Черновики

В SQLite добавляется таблица черновиков со следующими полями:

- `id`;
- `user_id`;
- `product_id`;
- `title`;
- `preview_image`;
- `state_json`;
- `created_at`;
- `updated_at`.

`state_json` содержит версионированное состояние конструктора:

```json
{
  "version": 1,
  "selectedSize": "M",
  "modelView": "front",
  "placedItemsByView": {
    "front": [],
    "back": []
  },
  "customDecorations": []
}
```

Пользовательские украшения в сохранённом состоянии используют серверные
`mediaId` и URL. Локальные object URL и содержимое изображений в JSON не
сохраняются.

### API

Все endpoints черновиков и пользовательского медиа требуют JWT текущего
пользователя и проверяют владельца ресурса.

- `GET /api/constructor-drafts` возвращает список метаданных черновиков.
- `POST /api/constructor-drafts` создаёт черновик.
- `GET /api/constructor-drafts/{id}` возвращает полное состояние.
- `PUT /api/constructor-drafts/{id}` обновляет существующий черновик.
- `DELETE /api/constructor-drafts/{id}` удаляет черновик.
- `POST /api/constructor-media` загружает пользовательское изображение.

Список не возвращает тяжёлое полное состояние. Полное состояние загружается
только при продолжении редактирования.

## Компоненты frontend

### Сервис локальных изображений

Отдельный модуль инкапсулирует работу с `IndexedDB`: запись, чтение, удаление и
очистку записей старше 24 часов. Конструктор не зависит от деталей IndexedDB.

### Сервис черновиков

Отдельный API-модуль отвечает за загрузку локальных изображений, создание,
обновление, получение и удаление черновиков. Он преобразует локальные ссылки
изображений в серверные перед отправкой состояния.

### ConstructorPage

Конструктор хранит `activeDraftId`, если был открыт через `draftId`. При
сохранении:

- без `activeDraftId` создаётся новый черновик;
- с `activeDraftId` обновляется текущий;
- при отсутствии авторизации открывается `AuthPopup`;
- после авторизации незавершённая операция сохранения продолжается.

### AuthPopup

Popup получает необязательный callback успешной авторизации. Обычные сценарии
входа не меняются; конструктор использует callback для продолжения сохранения.

### UnfinishedSurface

Mock-черновики заменяются данными API. Панель показывает только черновики
текущего пользователя, умеет удалять их и открывает выбранный черновик через
`draftId`.

## Согласованность и безопасность

- Пользователь не может получить, изменить, удалить или привязать чужой черновик
  или чужое медиа.
- Сервер валидирует существование товара и структуру состояния.
- Загрузка ограничивается разрешёнными MIME-типами и максимальным размером.
- Сначала загружаются медиа, затем сохраняется черновик. Если второй шаг не
  завершился, `pending`-медиа удаляется автоматической очисткой.
- После успешного сохранения frontend заменяет локальные ссылки серверными и
  может удалить уже загруженные локальные blobs.
- При потере сети локальные blobs и текущее состояние конструктора остаются
  доступными для повторной попытки.

## Проверка

### Backend

- CRUD черновиков работает только для владельца.
- Нельзя привязать чужое медиа.
- Создание и обновление корректно меняют связи медиа.
- Удаление черновика очищает только неиспользуемые и некупленные изображения.
- Очистка удаляет просроченные `pending`-файлы.

### Frontend

- Неавторизованный пользователь видит вход и после входа автоматически
  сохраняет черновик.
- Авторизованный пользователь сохраняет и сразу видит черновик в `unfinished`.
- Повторное сохранение обновляет черновик.
- Черновик восстанавливается через `draftId`.
- Несохранённые изображения не отправляются на сервер и остаются в IndexedDB до
  24 часов.
- Ошибка сети не уничтожает локальное состояние.

### Сквозная проверка

Проверить на мобильном viewport: добавить пользовательское изображение, закрыть
и снова открыть конструктор, сохранить после входа, продолжить редактирование в
`unfinished`, удалить черновик и убедиться, что чужой пользователь его не видит.
