# Frontend GARMENT BURO

Веб- и PWA-интерфейс проекта на Next.js 16 и React 19. Браузер обращается к backend через same-origin маршруты `/api/*` и `/uploads/*`; серверный адрес задаётся переменной `INTERNAL_API_URL`.

## Локальный запуск

Требуется Node.js 20+.

```bash
npm ci
INTERNAL_API_URL=http://localhost:8000 npm run dev
```

Приложение будет доступно на `http://localhost:3000`.

## Проверка перед коммитом

```bash
npm run check
npm audit
```

Команда `check` последовательно запускает ESLint, тесты и production-сборку.

## Переменные окружения

- `INTERNAL_API_URL` — внутренний URL backend, по умолчанию `http://backend:8000`.
- `NEXT_PUBLIC_USE_MOCK_DATA` — включает тестовые данные; в рабочей среде должен быть `false`.
- `NEXT_PUBLIC_IDENTITY_SESSION_V2_ENABLED` — включает новую серверную авторизацию.
- `NEXT_PUBLIC_CATALOG_WRITES_ENABLED` — разрешает запись каталога; требует новую авторизацию.
- `NEXT_PUBLIC_CRM_CABINET_ENABLED` — включает кабинет CRM; требует новую авторизацию.
- `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` — браузерный ключ Яндекс.Карт; ограничьте его разрешёнными доменами.

Полный набор переменных и безопасные значения по умолчанию находятся в корневом `.env.example`. Переменные с префиксом `NEXT_PUBLIC_` попадают в клиентскую сборку, поэтому секреты в них хранить нельзя.

## PWA-контуры

- публичные лендинги открываются в обычном браузере без установки;
- `/constructor` показывает установку, если страница открыта не в standalone PWA;
- основной manifest запускает `/constructor?source=pwa` и восстанавливает сохранённую ссылку на модель;
- `partner.garment-buro.ru` получает отдельный manifest с `id`, `start_url` и `scope` для `/partner`;
- `widget.garment-buro.ru` разворачивается как отдельное приложение на своём origin.

Service worker регистрируется только в production-сборке. Он не кэширует API,
uploads и storage; переходы по страницам используют сеть с отдельной offline-страницей.

## Кабинет партнёра

Маршрут `/partner` показывает текущего партнёра на верхней подложке и открывает
основную панель управления внахлёст. В кабинете доступны реальные баланс и история
выплат, заявки на вывод, заполнение банковских реквизитов, готовые ссылки на лендинги,
текущие правовые документы и обращение в поддержку. Изменение названия и описания
партнёра, подписчики и сообщества в этот интерфейс не входят.

## Основная структура

- `app/` — маршруты, layout и серверные точки входа.
- `components/` — интерфейсные компоненты по предметным областям.
- `hooks/` — клиентские контроллеры и переиспользуемое поведение.
- `lib/` — API-клиенты, состояние, конфигурация и предметная логика.
- `public/` — используемые статические ресурсы и PWA-файлы.

Для запуска всего проекта вместе с PostgreSQL, Redis, MinIO и backend используйте Docker Compose из корня репозитория.
