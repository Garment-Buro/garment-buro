# Новая кодовая база Garment Buro

Локальный кандидат новой кодовой базы подготовлен в ветке `codex/release-foundation`.
Кандидат публикуется отдельной веткой для ревью в GitHub.
Production не переключён; рабочие БД/S3 и сайт не менялись.
Эта страница описывает текущую рабочую копию на 20 октября 2026 года.
[Весь прежний журнал сохранён отдельно](release-refactoring-history-2026-10-19.md).

## Как посмотреть проект

Откройте [интерактивную карту](project-map.html), она работает без интернета.
«Оболочка страницы» показывает общие элементы и providers, «Код» объясняет
назначение файлов, «Пути данных» — запросы и сохранение данных. В графе сейчас
471 TS-файл и 194 компонента, достижимых по импортам. Это не означает, что все
они одновременно видны пользователю: показ зависит от маршрута, прав и состояния.

## Как открывается страница

Next.js выбирает маршрут в `frontend/app`. Например, главная и `/catalog`
вызывают `ServerPlatformEntry`: он получает первые карточки из backend до
отдачи HTML. На главной это товары, люди и сообщества; в каталоге — товары.
`PlatformEntry.tsx` — короткая точка входа в `ServiceHome`: передаёт первые
данные и выбранный раздел. Он не является отдельной страницей или provider.

`frontend/app/layout.tsx` добавляет общую оболочку: шрифты, шапку, подвал и
место модального окна. `AppEnvironmentProvider` передаёт окружение приложения.
`AuthSessionBootstrap` восстанавливает вход, `CartSyncBootstrap` согласует корзину;
это невидимые действия запуска, а не дополнительные страницы.
`SplashBoundary` управляет начальным экраном. Здесь же подключены PWA,
согласие на cookies и аналитика.

Начальные серверные чтения находятся в `frontend/lib/server/backend`.
Браузерные запросы используют общий HTTP-клиент и same-origin `/api`.
Next проксирует запросы в FastAPI; внешние платежи и доставка выполняются backend.
В FastAPI маршруты проверяют вход и права, сервисы выполняют операции,
repositories формируют SQL, модели и Alembic задают схему.

## Где хранятся данные

| Данные | Источник | Что остаётся в браузере |
| --- | --- | --- |
| Пользователи, каталог, избранное товаров/сообществ | PostgreSQL через API с проверкой сессии | Текущее отображение и состояние загрузки |
| Проекты конструктора | Документ в PostgreSQL, частные файлы в MinIO | Несохранённый ввод; перенос старых локальных записей запускается явно |
| Корзина и заказы | PostgreSQL; цена и оформление проверяются backend | Рабочий снимок корзины и восстановление незавершённой операции |
| Профили людей | PostgreSQL, фотографии через media API | Редактируемая форма; публикация профиля добровольная |
| Сообщества | Лендинги владельцев и коллекции в PostgreSQL | Фильтры, выбранные карточки и форма владельца |
| Производство и партнёры | PostgreSQL; файлы через MinIO | Состояние форм и выбранные справочники |

Redis используется как временное хранилище там, где это предусмотрено модулем;
он не заменяет основную БД. Постоянство корзины при остановленном Redis уже
проверено напрямую через Linux backend. JSONB внутри PostgreSQL — формат
структурированного документа, а не отдельная файловая база. Исторические
инструменты импорта и явный перенос локальных проектов сохраняются для данных
пользователя; новые записи не возвращаются в старый файловый runtime.

## Какие интерфейсы считаются основными

Основной редактор товаров — **производство → «Пресеты»**.
`/admin/models` перенаправляет туда. Общие формы сохраняют отдельные права
производства и identity-управления; это не два независимых редактора товара.
Прежние `CatalogScreen`, `LandingPage`, `/admin/editor`, backend SQLite facade
и файловые landing settings удалены. Старый backend `/admin` больше не регистрируется.
Действующие защищённые `/api/production/admin/*` относятся к новому кабинету.

«Люди» — публичные профили пользователей с редактированием своего профиля.
«Сообщества» — лендинги владельцев с коллекциями. Надбавка за принт/надпись
пока сохраняет согласованные 80 ₽ и текущую формулу. Размерная настройка
154–206 означает рост человека в сантиметрах.

Авторизация использует общую схему аккаунтов PostgreSQL. Восстановлена точная
миграция из работающего образа и добавлено объединение веток в единый head
`20261020_0081`. Email OTP остаётся текущей формой входа; фиктивная вкладка
Telegram удалена. Backend сохраняет пароль Argon2id и подписанный Telegram-вход
по отдельному флагу. Телефонный вход выключен до появления настоящего провайдера;
контактный телефон профиля не подтверждает право входа.

## Запуск и диагностика

ASGI entrypoint — `app.main:app`. Миграции выполняются отдельной командой,
API сверяет Alembic head до работы и не создаёт таблицы при импорте.
Lifespan управляет соединениями и фоновыми задачами, освобождая ресурсы и при
частичном запуске. API и workers пишут структурированные JSON-события stdout;
request ID связывает запрос, ответ и ошибку. Access event содержит шаблон
маршрута без query string, тела и токенов.

Действующие Compose: `docker-compose.local.yml` и
`deploy/docker-compose.server.yml`. Секреты задаются вне исходников.
Readiness проверяет включённые БД/storage и состояние фоновых задач;
успешный readiness сам по себе не подтверждает оплату или доставку.

## MinIO остаётся

Фотографии и файлы сохраняются в MinIO по вашему решению. Открытый
[репозиторий MinIO](https://github.com/minio/minio) архивирован 25 апреля 2026 года,
но установленный сервер от этого не отключается. Это ограничение сопровождения
Community upstream, а не обязательное требование переносить ваши данные.

Подготовлена воспроизводимая поставка из официальных исходников security release
от 15 октября 2025 года: commit, checksum архива и Go image digest закреплены.
Настоящий linux/amd64 образ собран; local Compose и CI используют тот же
Dockerfile. Серверный release требует заранее подготовленный `MINIO_IMAGE`.
Bootstrap бакетов выполняет backend; отдельный mc-образ больше не нужен.
На тестовых томах проверены обновление, restart, приватность файлов и отдельный
согласованный PostgreSQL/MinIO restore. Рабочее хранилище не обновлялось.

Клиент MinIO имеет настраиваемые пределы ожидания соединения 3 секунды и паузы
чтения 15 секунд. Чтение допускает один повтор; загрузка и удаление после
неоднозначного ответа не повторяются. TLS и собственный CA сохраняются.
Это исправление проверено реальным локальным HTTP с зависаниями и ошибками;
оно не доказывает, что прежняя медленная главная была вызвана MinIO.

## Почему отдельный исторический код сохранён

Offline-инструменты читают прежние БД/JSON для явного переноса пользовательских
данных; они не подключают старый каталог или backend в работающий API.
Неиспользуемая настройка `legacy_database_url` с `ecommerce.db` удалена.
SQLite-ветки ORM нужны изолированным тестам; основной runtime использует
PostgreSQL, а aiosqlite отсутствует в production lock.

Production demo provisioning выполняется отдельной операторской командой.
Демо-заказы маркированы и отделены от оплаты, публичного каталога и настоящих
производственных данных. Это управляемые учебные сценарии, а не подмена
серверного хранения браузерным кешем. Миграции, перенос старых сессий в пределах
настроенного grace period и восстановление локального черновика сохранены
для непрерывности работы пользователя.

## Граница публикации

Подготовлен и проверен локальный кандидат. Для утверждения «новый релиз работает
на сайте» ещё нужны Actions/GHCR для опубликованной ревизии, проверка рабочего
объёма и окна восстановления, публичные браузерные сценарии и целевой телефон.
Реальные операции платежей, доставки и внешних сообщений проверяются отдельно
с активированными провайдерами. Эти действия не выполнялись в ходе локальной
подготовки; рабочие БД/S3 и сайт не менялись.

Уже проверенные локально release/backup CLI, настоящий Nginx и историческое
checkpoint recovery описаны ниже. Возврат к checkpoint отбрасывает поздние
записи; он не является автоматическим откатом без потери новых данных.
Сбой повторного открытия сайта после commit сохраняет новые образы, metadata
и принятую публичную запись, удерживая обслуживание закрытым до ремонта.
