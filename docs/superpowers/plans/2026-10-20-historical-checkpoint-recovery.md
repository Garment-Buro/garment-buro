# Исторические образы: обновление и восстановление checkpoint

20.10.2026 проверен неизменный снимок 1696 файлов на собственном rootless Docker.
Использованы настоящие прежние backend/Next-образы, экспортированные read-only;
архивы, OCI index → manifest → config и все слои проверены по SHA-256.
Рабочие БД, файлы и настройки не читались. Тестовые ключи и данные изолированы,
выход к провайдерам закрыт внутренней сетью Compose.

Старые образы подняли схему `20261012_0056`. Созданы native fixtures:
два пользователя, товары, корзина, 10 000 заказов и три объекта MinIO.
Старые startup guards получили синтетические migration markers;
это предусловие fixture, а не проверка настоящих CLI импорта.
Для storage bootstrap использован текущий minio-init: прежний образ такой
утилиты не содержит. MinIO — закреплённая сборка нового релиза из исходников;
API, Next и Alembic-проба используют настоящие прежние образы.
HTTP проверил пользователя, корзину, историю, состав заказа и старый product API.
Настоящий прежний Next открыл `/` и `/mycollection`, все 22 JS/CSS скачаны
и хешированы. В прежнем Next нет `/catalog`; текущий Next проверяет этот путь.

Неизменённый `backup-server.sh` создал проверенный комплект из 6 файлов.
Шестой файл — архив пустого исторического `/app/uploads`; legacy SQLite
и пользовательские файлы не читались. После возобновления приложения
содержимое всех таблиц совпало со снимком до backup; setup jobs не перезапускались.

Текущие образы обновили ту же БД до `20261020_0081` и обслужили прежние данные
через API/Next: история стала paginated 24 вместо старого списка 10000,
корзина и принятый состав заказа сохранились; главная, каталог и текущие assets доступны.
Затем fixture изменил заказ и создал новую версию объекта после checkpoint.
Alembic-проба старого образа сначала приняла 0056, затем отказала на 0081
с сообщением `Database is not on all head revisions`. Проба не изменила таблицы.
Таким образом, совместимость старого приложения с новой схемой **не заявляется**.

Согласованный checkpoint восстановлен в отдельный Compose project и свежие
PostgreSQL/MinIO volumes. До старта API совпало содержимое всех 103 исторических
таблиц. Восстановлены прежние head и точные config ID обоих образов,
10 000 заказов, три объекта, две версии, metadata/tags и public/private доступ.
Старый API/Next прошёл повторно, 22 asset SHA-256 совпали с исходными.
После restart API с остановленным Redis доступ к прежним данным сохранился,
следующий заказ получил ID10001.

Возврат к checkpoint намеренно отбрасывает записи после backup. Это не
автоматический rollback без потери новых данных. Для релиза нужны согласованное
окно обслуживания и блокировка внешних writers; public maintenance gate,
рабочий объём/время восстановления, GitHub Actions и публичный E2E ещё открыты.
Отдельный полный Linux suite 1409/0skip прошёл предыдущим этапом; здесь он
не повторялся, runtime-исходники не изменялись. Пять неуспешных fixture-попыток
сохранены отдельно; проверенный результат относится к executed-driver-6.py.
Свои контейнеры, volumes, сети Compose, VM/диски и приватная CLI-конфигурация
удалены без ошибок. Ни commit/push, ни развёртывание не выполнялись.
