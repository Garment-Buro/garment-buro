# Постоянные изображения дизайна в корзине и заказе

Подтверждён разрыв: конструктор читает до8МБ в data URL, cart/order ограничивают
customization64КБ. У проекта строки изображений — временные URL; cart/order
сохраняют их как есть. В JSON нет FK, поэтому project cleanup не видит ссылку
принятого заказа и может удалить используемый файл.

## Контракт

Файл хранится в закрытом MinIO, метаданные в MediaObject. DesignAsset даёт
непредсказуемую ссылку только на один файл; в БД хранится digest токена.
Токен изображения не открывает корзину или аккаунт. CartDesignAsset и
OrderDesignAsset — настоящие FK для удержания файла. Временная ссылка S3
не становится сохранённой ссылкой заказа. Анонимный покупатель может загрузить
свой файл; импорт существующего private media требует identity владельца.

Неиспользуемые assets имеют TTL. Ссылка активной корзины удерживает файл до
истечения корзины; принятый заказ удерживает независимо от TTL и удаления
аккаунта. Привязка и очистка сериализуются блокировкой asset/media; пакетные
выборки ограничены. Состояние очистки не хранится в Redis или браузере.

## Этапы

- [x] SQL foundation: ORM, Alembic0069, capability tokens, пакетные привязки,
  ограниченная очистка metadata с блокировками, реальные PostgreSQL гонки и
  upgrade/downgrade. Откат непустой новой таблицы не должен тихо терять ссылки.
- [x] Upload/content/import API с приватным storage, действительным декодированием

- [x] Атомарные cart/order FK-привязки и защита файлов принятых заказов от cleanup.
- [x] Frontend: перед покупкой сохранить изображения, заменить base64/временные
  URL на постоянные ссылки, обработать ошибку/повтор и смену аккаунта.
- [x] Локальные PostgreSQL/MinIO + production browser: файл>64КБ, гость/владелец,
  reload проекта, upload/retry/cancel, импорт ID, сохранение из корзины в проект,
  повтор HTTP checkout, FK заказа; обновление карты/журнала.
- [x] Исключить приватные API и подписанные изображения из публичного кеша Next:
  общий компонент customer media, конфигурация оптимизатора, proxy, сравнение
  настоящего standalone runtime до и после изменения.
- [ ] Полная покупка через публичный UI с действующей оплатой, истечение временной
  ссылки и удаление проекта/аккаунта в этом же сценарии. Очистка orphan,
  ограничения размера, rollback и удаление аккаунта уже имеют отдельные native
  проверки; это не доказательство опубликованного сквозного сценария.
  Перед публикацией проверить исключение capability URL из edge/access/error
  логов и аналитики. Backend access event использует шаблон маршрута; реальные
  настройки внешнего reverse proxy ещё не проверены.

Первый этап не исправляет пользовательский поток целиком; до завершения всех
пунктов нельзя объявлять изображения в корзине/заказе постоянными.
Формулу80₽, дизайн интерфейса, stage/commit/push/deploy не менять.
