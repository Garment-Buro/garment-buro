# Настоящие товары на главной и в каталоге

Часть полного нового релиза из `docs/release-refactoring.md`. Выполнение в текущей
сессии, последовательно; production пока не переключается.

**Цель:** убрать локальные цены и ID одежды из пользовательского сценария,
показывать опубликованные товары PostgreSQL, сохранять избранное в аккаунте.

**Граница данных:** `/api/catalog/products` возвращает ограниченную страницу
карточек, а не прежний документ каталога. Сортировка и фильтры выполняются в SQL.
Cursor содержит позицию и отпечаток фильтров, валидируется до SQL; OFFSET не нужен.
Карточка содержит одну готовую публичную картинку, массивы цветов/тегов, точную
цену в десятичной строке. Приватные и незавершённые медиа не публикуются.

## Серверная витрина

- [x] Контрактные проверки сначала: 404 до реализации; затем опубликованность,
  пагинация четырёх сортировок с одинаковой ценой, поиск без SQL wildcard,
  фильтры группами, ограниченные batch IDs, плохие/чужие cursor, приватные медиа.
- [x] `catalog/public_policy.py`: единая видимость товара для каталога/избранного.
- [x] `catalog/storefront_schemas.py`: ограничения параметров и типизированные
  ответы. `storefront_repository.py`: ограниченные SELECT карточек/одного медиа,
  без вариантов, описаний, пересчёта ткани или запросов на каждый товар.
- [x] `storefront_service.py`: cursor и отображение медиа в S3 URL, без прежней
  `/uploads` оболочки. `storefront_router.py`: маршруты, HTTP-ошибки, DI.
- [x] Настоящий PostgreSQL: те же фильтры/медиа/пагинация, отсутствие дубликатов,
  ограниченное число SQL, Alembic/schema check после нужных индексов.

## Интерфейс и избранное

- [x] `lib/api/storefront.ts`, `favorites.ts`: только same-origin backend API.
  Ограниченное получение статусов избранного для загруженных товаров; список
  избранного тоже постраничный, без загрузки всех ID на старте сайта.
- [x] Разделить получение данных, сетевое состояние и `ServiceProductGrid`.
  Ошибки/загрузка/пустые данные различаются; запросы отменяются при смене поиска;
  состояние другого аккаунта не показывается и не переносится в новый.
- [x] Главная использует небольшую страницу реальных товаров. Каталог получает
  страницы с backend, динамические категории/цвета и серверные фильтры.
- [x] Карточка передаёт `productId` в конструктор, share ссылается на этот товар.
  Сердечко подтверждается backend; гость получает предложение войти.
- [ ] Удалить `serviceFavoritesStore` с демо ID и данные демо-товаров после
  проверки импортов. Не сопоставлять их с реальными по названию/позиции.
- [ ] Проверить frontend tests/tsc/eslint и браузер: реальный backend PostgreSQL,
  два клиента/аккаунта, мобильные размеры, поиск/пагинацию/конструктор/ошибки.
