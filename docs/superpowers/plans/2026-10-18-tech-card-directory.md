# Техкарты: краткий список и отдельная исходная версия

Локальный этап нового релиза. Основной редактор товаров остаётся производство → «Пресеты». Техкарты — производственные инструкции, а не ещё один редактор товара. Stage/commit/push/deployment не выполнялись; завершение этого этапа не означает готовность общего выпуска.

## Исправленная загрузка

Старый production GET `/tech-cards` возвращал все карты со всеми версиями и операциями. Экран дополнительно загружал первые 100 производственных моделей, искал в них подписи, фильтровал/сортировал массивы и по этим неполным данным решал, можно ли создать карту. Новая версия копировалась из уже загруженной истории. Серверные команды также гидратировали всю историю карты под блокировкой.

Теперь GET `/api/production/admin/assortment/directory/tech-cards` возвращает краткую страницу: ID, модель/название, код/активность, номер/статус/название последней версии, число её операций и номер текущего черновика. Ни revisions, ни checkpoints в карточке нет. Название модели приходит через JOIN; состояние относится именно к latest_revision_number, даже если последняя версия отклонена. Поиск по модели/коду/названию последней версии, активность, статус и сортировки выполняются в SQL. Страница по умолчанию 24, максимум 100. Cursor включает фильтры/сортировку и пару значение + ID, устойчив к равным значениям и не принимается для другого списка.

GET `.../directory/tech-card-models` — отдельный короткий список моделей, у которых нет карты. NOT EXISTS проверяется в SQL, в том числе для неактивной карты: скрытая карта не освобождает модель. Поиск и продолжение независимы от списка карт. Новая карта требует явного выбора модели; пустой результат текущего поиска не отключает создание. При конкурирующем создании сервер повторно проверяет модель под блокировкой и отклоняет вторую карту.

GET `.../tech-cards/{id}/revision-source` запрашивается только при создании новой версии. Он возвращает метаданные карты, текущий номер и одну последнюю неотклонённую версию с операциями по position. Это может быть предыдущая опубликованная версия, если последняя отклонена. Полностью отклонённая история возвращает source=null: новая версия начинается с пустой операции, но использует настоящий expected_latest_revision. Если уже существует черновик, API возвращает 409; неизвестная карта — 404. Чтения имеют no-store и прежнюю production authority require_system_admin.

Список карт и список доступных моделей — по одному SELECT, limit+1, без ORM identity map. Source — два SELECT для одной карты/версии. Контракт операций остаётся максимум 200; превышение не обрезается незаметно. Старый production GET `/tech-cards`, его unbounded service/repository методы и прежние frontend типы массива истории удалены. POST создания, новой версии и публикации сохранены. Схема БД не менялась, head0072; frontend/backend требуют согласованного выпуска.

## Команды и неизменяемость истории

Writer блокирует и обновляет актуальную ORM запись карты через populate_existing. Создание версии читает только текущий draft и published metadata, добавляет новую revision напрямую по tech_card_id и проверяет expected_latest_revision. Публикация/отклонение читают запрошенную версию и её операции; публикация отдельно находит опубликованную версию для архивирования. Коллекция всей истории больше не читается и не подменяется частично загруженной relationship.

Сохранены последовательность номеров, запрет второго draft, based_on опубликованной версии, архивирование прежней публикации, снимки операций и audit events. Объём работы команды зависит от выбранной версии, а не от длины истории. Устаревшая запись в identity map не обходит проверку версии.

## Frontend и оболочки

`AdminTechCards → useTechCardDirectory → usePagedCatalog` отвечает за список и публикацию. Ошибка продолжения оставляет карточки; invalid cursor требует явного обновления; новый поиск отменяет старый. Подтверждённая публикация не повторяется из-за отказа чтения списка после неё.

`TechCardEditor` выделен из прежнего монолитного экрана. Он владеет одним source GET, его отменой, ошибкой/повтором и черновиком. До полного правильного ответа форма не открывается. Закрытие отменяет чтение; поздний ответ не возвращает редактор. Production sessionEpoch остаётся общей границей жизни кабинета. Ни нового Provider, ни новой оболочки страницы нет.

`ReferencePicker` дополнен видом «модели без техкарты»: отдельный серверный adapter, выбранный ID/название сохраняются при пустом поиске и не зависят от первых 100 вариантов. `techDirectory.ts` проверяет короткие DTO и source (свой ID, номера, полный набор полей операций, уникальные позиции, цены/время). `techCardEditor.ts` — чистое преобразование source в форму и whitelist payload, без React/HTTP.

Раньше копирование версии применяло employeeStation к stage_code/role_code и незаметно заменяло sewing/qc/application на workshop. Теперь эти коды сохраняются; прежнее назначение доступно в select отдельно от нового объединённого участка. Это не меняет справочник сотрудников. Decimal времени и стоимости сохраняет точность до 0,01. Payload не отправляет старые ID операций или read metadata.

Запись имеет синхронный lock; поля, закрытие и фоновые действия экрана отключены до результата. Ошибка оставляет тот же черновик и ожидаемый номер версии. Действующая граница 200 операций видна в форме: добавление отключается при достижении максимума, существующие операции можно редактировать/удалять.

## Проверки и оставшаяся работа

Полный backend: **1075 passed, 0 skipped**, 311,41 с на Python 3.12.12 со свежими PostgreSQL17 и настоящим MinIO. Временные процессы, данные и приватная конфигурация удалены. Ruff/format всех 649 Python файлов прошли. Профильный native набор: 42 passed/0skip; четыре новых контракта исполняются на SQLite и PostgreSQL. По 130 карт и свободных моделей; у одной карты история из 130 версий, в исходной опубликованной — 200 операций, в последней отклонённой — 17. Проверены сортировки/совпадения, Unicode/literal поиск, cursor scope, отказ от полной истории, SQL count/identity map, копирование правильной версии и настоящие create/publish/discard/CAS команды. Guest/identity-only получают 401, production manager — 403.

Полный frontend: **591 passed, 0 skipped**, lint без ошибок и production build/TypeScript с тремя release flags. Шесть новых исполняемых проверок read DTO/transport и преобразования черновика: код/роль, инструкция и Decimal не теряются, ID старых операций не записываются, новая карта требует явного modelId. Сохраняются прежние предупреждения CustomerMediaImage alt, fallback Alumni Sans SC и Starlette test client.

`check:admin-catalog` прошёл на настоящем standalone Next/Chromium с синтетическим HTTP API. Карты и свободные модели доступны за пределами 100, страницы по 24. Отказ продолжения/повтор, invalid cursor/обновление, поздний поиск, отсутствие source prefetch, отмена закрытого source, failed/incomplete/409 source без пустой формы. Проверены сохранение sewing/qc и 12,34/3,25, failed save с тем же черновиком/версией, блокировка повторной записи/закрытия/фона, максимум 200 операций и явный выбор модели 1130 при пустом поиске. Подтверждённая публикация не повторяется при failed refresh. Формы — 320/390/736/1280 px и короткий landscape 736×390; прежние сценарии пресетов, складов, кабинетов и двух вкладок тоже прошли. Настоящие SQL, права и команды проверены отдельно backend тестами.

Первый полный прогон выявил общий счётчик попыток входа у тестовых приложений, использующих одну PostgreSQL и одинаковый test pepper. Каждый fixture теперь получает свой ephemeral pepper; production limiter не ослаблен. Cleanup охватывает также отказ входа, чтобы ошибка setup не оставляла бизнес-данные следующему тесту. Identity-only проверяется настоящими заголовками выданного тестового access token, без производственной cookie.

На момент этого этапа лекала ещё использовали первые 100 моделей и полный массив покрытий. Последующим [этапом лекал](2026-10-18-pattern-directories.md) они перенесены на страницы/окно сетки, и последний старый production GET моделей удалён. Query plans/индексы на производственном объёме, другие справочники, крупные формы и общие ворота выпуска остаются открытыми. Docker/Actions, опубликованный сайт, телефон, внешний writer/backup restore и реальная оплата этим этапом не подтверждены.
