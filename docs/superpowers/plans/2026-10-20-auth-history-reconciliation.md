# Согласование истории авторизации

Рабочая копия `codex/release-foundation`, 20 октября 2026 года.
Stage/commit/push/deploy не выполнялись. Рабочая БД не читалась и не менялась.

## Причина

Работающий backend-образ содержит миграцию `20261012_0056_multi_channel_auth.py`,
которой не было в ветке нового релиза. Прежняя проверка отдельной синтетической
БД показала `unknown revision`. Все 55 общих файлов до `20260929_0055` совпали
по SHA-256. Одного копирования миграции недостаточно: без соответствующих
моделей и сервисов новый API потерял бы поддержку существующих способов входа.

## Изменение

Миграция `20261012_0056` восстановлена байт в байт из исходников работающего
образа. Новая merge-ревизия `20261020_0081` объединяет её с `20261019_0080`.
Старые ревизии не перенумерованы; `stamp` не применяется. Единственный head
проверяется тестом. Merge удаляет только дублирующий неуникальный индекс
`password_credentials.user_id`: уникальное ограничение уже обеспечивает поиск.

Модели, репозитории, сервисы и реестр способов входа согласованы с этой схемой:

- email OTP сохраняет прежний формат digest и работает через зашифрованный outbox;
- пароль использует Argon2id, ограниченное число параллельных вычислений,
  счётчик неверных попыток и блокировку;
- Telegram проверяет HMAC и возраст подписи, связывает вход с существующим
  аккаунтом; включается отдельным флагом и требует настройки бота;
- телефонный вход выключен до появления настоящего провайдера доставки кода.
  Телефон в контактных данных профиля не подтверждает владение номером для входа;
- уведомления получают транспорт через единый реестр. Старый адаптер SMTP
  конструктора удалён, действующий SMTP integration сохранён;
- удаление профиля очищает новые credential/identity данные.

Из действующей формы входа убрана фиктивная вкладка Telegram. Браузерная форма
сохраняет email OTP, отмену запросов, согласование сессий и защиту от поздних
ответов после смены аккаунта. Добавление настоящего UI для других методов —
отдельная продуктовая задача; наличие API не означает доступность кнопки.
Старые SQLite facade, редактор лендинга и legacy order bridge не возвращались.

## Локальные проверки

63 теста без пропусков проверили безопасность identity, миграцию пользователей,
методы входа, outbox/fulfillment, граф Alembic и HTTP-контракт identity.
Широкий unit/contract запуск: 1067 passed, 189 skipped, 238,19 с. Пропуски
относятся к сценариям с внешней БД; этот запуск не заменяет полный release gate.

Frontend tests, ESLint изменённых файлов, production Next build и TypeScript
прошли. Новое число frontend-тестов отдельно не фиксировалось; прежние 626
относятся к предыдущему этапу. Ruff check и format прошли.

## Настоящий Linux / PostgreSQL / HTTP

Проверка выполняется в собственном свежесобранном backend-образе и PostgreSQL17.
Внешние SMTP, Telegram delivery, платежи и доставка не вызываются; Telegram HMAC
проверяется с синтетическим ключом. MinIO в этом тесте выключен.

Четыре начальных состояния: пустая БД, общий предок `20260929_0055`,
схема работающего образа `20261012_0056`, прежний head ветки `20261019_0080`.
Тест использует настоящий Alembic и сравнение полной схемы с metadata.
До обновления сохраняются исходные колонки/строки аккаунтов, ролей, refresh,
OTP, паролей, внешних identity и outbox; после обновления сравниваются все
прежние значения, допускаются только новые колонки/строки backfill.
Через настоящий uvicorn проверяются старые access/refresh/OTP, вход с паролем,
повторное использование Telegram identity и отказ выключенного phone provider.

Все четыре сценария прошли. Для каждого полная схема совпала с metadata,
сохранились прежние значения и прошли перечисленные HTTP-запросы.
Настоящий backend Dockerfile с hash-locked requirements собран native linux/amd64;
737 файлов контекста сверены по SHA-256. Image ID:
`sha256:9eb7ad6a3ae888f3ab8658bdccb412e14c4f264f9877ac9f53f7ae2ae494f722`.
Тест выполнялся из самого образа, без подмены `/app` исходниками с хоста.

Builder: 768 MiB RAM, swap0, CPU0,5; лимиты подтверждены через Docker inspect
и cgroup. Он удалён до запуска БД/API. PostgreSQL: 192 MiB; текущий процесс
проверки вместе с uvicorn: 384 MiB, CPU0,5. Своя сеть internal, опубликованных
портов нет, секреты синтетические в конфигурации 0600. Собственные контейнеры,
volumes, сеть, builder, образ, исходники и конфиги удалены. Исходные 14
контейнеров совпали по ID, image ID, StartedAt и RestartCount.

Первые две попытки со старым Python runtime дошли до схемы, но не доказали HTTP:
старый FastAPI не содержит RouteContext, который использует текущая
observability. Эти неудачные попытки также завершены и очищены. Поэтому их
результаты не подменяют успешную проверку настоящего нового образа.

## Границы

Объединение схемы не делает прежний образ совместимым с новым head.
Строгая проверка Alembic продолжает запрещать такой автоматический возврат.
Нужны проверенный полный DB/S3 restore либо отдельно проверенная совместимость,
полный HTTP через Linux Next, актуальный CI и публичные сценарии релиза.

MinIO остаётся выбранным хранилищем по решению пользователя. Архивирование
[официального Community-репозитория](https://github.com/minio/minio) не означает
остановки существующей установки. Воспроизводимый источник серверного образа
и проверка резервного копирования остаются задачами выпуска; переход на другого
поставщика или платную редакцию не согласован и не выполнялся.
