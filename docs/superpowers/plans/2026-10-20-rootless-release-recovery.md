# Release CLI и возврат на настоящем rootless Docker

Проверка 20.10 выполнялась только в отдельной VM с синтетическими данными.
В remote-deploy.sh обнаружены ещё две ветки Compose start: возврат paused API
и workers. Через зависимости могли повторно выполняться завершённые setup jobs.
Регрессионный тест сначала воспроизвёл ошибку. Обе ветки теперь используют
up -d --no-deps --no-recreate --pull never --wait. Сохранены старые контейнеры,
их фактические image/environment, даже если конфигурация или теги изменились.

109 профильных проверок прошли без пропусков: 67 release и 42 backup/verifier.
Проверяются частичная остановка, INT/TERM, миграции, dormant apps/workers,
сохранность контейнеров и явные ошибки recovery. Ruff и bash syntax прошли.

На Docker 29.9.1/Compose 5.6.0, uid 1000/name=rootless выполнены настоящие
remote-deploy.sh, backup-server.sh и verify-backup.py без подмены команд.
Три сценария: сбой storage-init до миграции (41), unhealthy worker после HTTP
проверок кандидата (1), успешное переключение (0). Ранний recovery сохранил ID,
image/environment и времена запуска завершённых setup jobs. Поздний recovery
остановил кандидата, дождался migration barrier, проверил Alembic прежнего
образа и вернул прежние API/workers. Выключенный project-media-worker не остался
работать после неудачи. При успехе оба workers и API используют candidate image.
PostgreSQL/Redis/MinIO контейнеры не пересоздавались. Каждый запуск сделал
проверенный пятифайловый backup. 10 000 заказов, история, receipt, избранное,
корзина, три файла, две версии и public/private политики сохранились.

Граница доказательства: registry настоящий, но локальный fixture внутри VM.
Имя ghcr.io разрешалось только внутри тестового daemon в адрес своего registry;
реальный GHCR не использовался, порты registry не публиковались. Worker-команды
заменены в fixture на sleeping processes, один healthcheck принудительно падает;
доставка, платежи и отправка сообщений не выполнялись. Baseline/candidate
используют один проверенный runtime, у кандидата изменена только image label:
это доказывает lifecycle скрипта, не совместимость исторического приложения
с новой схемой. Полный suite 1406 и образы были до правок backup/recovery.
Текущий deploy исполнялся из нового снимка; встроенные unit-тесты образа старые.

Снимок 1694 файлов сверён до/после. Все свои контейнеры, volumes, registry,
VM с дисками и приватная конфигурация удалены. Рабочие данные не читались.
CI, исторический rollback либо проверенное полное восстановление прежнего
приложения/данных, рабочий объём и опубликованный browser E2E ещё открыты.
