# Согласованные данные редактора товара

18 октября, следующий этап общего release refactor. Stage/commit/push/deploy
не выполняются. Следующий этап уже объединил форму: см. 2026-10-18-shared-product-editor.md.

## Найдено и исправлено

1. Новый редактор соединял `ProductDetailResponse` с references вариантов
   из ранее прочитанного списка по позиции в массиве. Теперь защищённый GET
   товара возвращает `CatalogAdminDetail`: актуальные slug/category/model,
   ID/SKU/size/fabric каждой вариации и её media/геометрию одним чтением.
   Identity staff и системный production admin используют общий service.
2. Административное `stock_quantity` — физическое количество, отдельно
   `reserved_quantity` и вычисляемое `available_stock_quantity`. Публичный
   mapper/checkout по-прежнему показывают доступность по ткани. Вычисленное
   наличие не становится редактируемым физическим остатком.
3. `update_product` удалял все SKU и создавал их заново, даже если прислан ID.
   Теперь явно указанные собственные ID обновляются на месте, сохраняют SKU,
   отсутствующие варианты удаляются, новые без ID создаются. Чужие/повторные
   ID отклоняются до изменения. Запрет изменений при активных резервах остался.
4. Новый frontend не имеет параллельных `variants/variantReferences` и не
   берёт ссылки из карточки списка. Payload/matrix вынесены в чистый доменный
   `presetEditor.ts`. Совпадающий вариант сохраняет ID, media, геометрию и
   физический остаток. Исторические одинаковые reference pairs не схлопываются.
   Деталь имеет deadline/cancel и авторизацию production сессии.
5. Старый frontend тоже отправляет полученные ID и CRM references; сохраняет
   отсутствующие в его UI source/tags/slug/category/model/composition/model_info,
   sizes/colors/visibility/type и основные изображения. Раньше редактирование
   названия могло обнулить их, включить скрытый товар и сменить источник.

  native stable IDs/SKU/raw stock, создание, отказ чужого/повторного ID.
  Финальный полный backend:1027 passed,0 skipped за271.15s на Python3.12.12,

  отдельно pytest; этот браузерный стенд не объявляется публичным E2E.

## Продолжение объединения UI

- Объединить саму форму и общий контракт операций, а не перенаправлять всех
  пользователей в `/production`: identity manager имеет catalog.write/CRM,
  но production номенклатура требует личный системный admin код. Простое
  перенаправление лишит менеджера доступа. Две точки входа могут временно
  показывать одну общую форму с разными адаптерами авторизации.
- Одна общая форма должна покрыть используемые constructor/gallery/variant
  media и геометрию. Не переносить ненужные старые desktop/video поля без
  проверки потребителей. После покрытия удалить старые формы/hooks/options.
- Учесть существующие товары без garment_model_id: старый writer допускает
  физический запас, новый POST/PUT PresetWriteRequest требует модель. Не
  превращать сохранение названия в принудительную смену товарной модели.
- Убрать first100 в выборе моделей/тканей, unbounded список лендингов и их
  membership; после нового detail списку достаточно variant_count/артикула.
- Optimistic concurrency продукта пока отсутствует. Parent lock сериализует
  записи, но не обнаруживает старую форму; необходим отдельный version/CAS
  контракт. Сохранение ID само по себе этого не решает.

Общий релиз остаётся открытым: Docker/Actions/public runtime, телефон,
предыдущий образ/схема, реальный backup/внешние писатели и платёжный E2E.
