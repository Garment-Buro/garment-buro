Статус: защита реализована; общий выпуск не завершён.
Production не переключён, рабочая БД и пользовательские файлы не менялись.
Stage/commit/push/deploy не выполнялись.

## Исправление восстановления

Прежде ошибка после попытки миграции возвращала прежние приложения и workers
без проверки принятой ими схемы. У нового API строгая проверка Alembic head:
даже добавление индекса может сделать прежний образ незапускаемым.

Теперь скрипт отмечает начало миграции до вызова Compose. При ошибке сначала
останавливает уже запущенные приложения и workers кандидата. Затем проверяет
и удаляет только именованный контейнер миграции этого выпуска: остановка
Docker-клиента после INT/TERM не гарантирует остановки его контейнера.
Ошибка обнаружения или удаления оставляет прежние writers остановленными.

Перед возвратом старых writers выполняется команда **прежнего backend-образа**:
`python -m alembic -c alembic.ini current --check-heads`.
Она сравнивает реальную ревизию БД с head из самого прежнего образа.
API и фоновые задания не запускаются; зависимости не пересоздаются,
образ не скачивается. Ожидание ограничено 60 секундами, вывод CLI скрыт,
чтобы не выводить настройки БД. Оставшийся после ошибки контейнер проверки
удаляется по точному имени.

Несовпадение, недоступность БД, timeout и отсутствие поддержки команды
останавливают автоматический возврат. Сообщение указывает каталог восстановления;
файл `storage-backup.path` в нём содержит путь к архиву. Схема не понижается автоматически.
При сбое до попытки миграции сохраняется возврат существующих контейнеров
с их исходным образом/окружением. После переключения сохранённые descriptor
и `.release` возвращаются до проверки старой схемы, включая поздний сбой metadata.

новые поля OTP и каналы уведомлений. Историю, модели и работающие возможности
нужно согласовать перед выпуском; чистая БД с новым head этого не доказывает.

## Границы

Проверка head необходима для запуска, но не доказывает совместимость форматов
данных, конфигурации и внешних действий workers. Полный контейнерный cutover,
восстановление согласованного DB/S3 bundle на рабочем объёме и измерение простоя
остаются отдельными gates. Кандидат использует текущий `.env`; возврат прежних
секретов и настроек не выполняется автоматически. Общий backend-набор после
нового storage bootstrap ещё не повторялся.

Удаление контейнера подтверждает остановку клиентского процесса миграции,
но не завершение уже отправленного COMMIT/rollback в PostgreSQL. Перед полным
gate нужен барьер завершения этой транзакции и проверка прерывания активного DDL;
одна проверка номера head не устраняет это окно.

На следующем этапе барьер добавлен и проверен на настоящем PostgreSQL,
включая SIGKILL клиента во время активного DDL. Текущий результат —
138 локальных и 4 PostgreSQL теста без пропусков; см.
[завершение миграции](2026-10-19-migration-completion-barrier.md).
Приведённые выше 100 тестов и dump/restore относятся к предыдущему снимку.
