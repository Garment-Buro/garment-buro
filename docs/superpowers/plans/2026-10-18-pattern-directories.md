# Лекала: страницы моделей/файлов и ограниченный участок сетки

Локальный этап нового релиза. Основной редактор товаров — производство → «Пресеты». Лекала остаются отдельным производственным справочником. Stage/commit/push/deployment не выполнялись; общий релиз ещё не завершён.

## Что было изменено

Старый экран загружал первые 100 полных производственных моделей и весь массив лекал, фильтровал их в браузере и заранее строил все клетки всех размеров, включая закрытые блоки. Большой диапазон размножался как ширина × длина × варианты рукава. После изменения диапазона часть старых файлов пропадала из сетки, хотя оставалась в БД. Редактирование также заменяло сохранённое имя файла его кодом.

Теперь загрузка разделена на краткий список моделей, выбранный участок сетки, отдельный список файлов и редактор одной записи. Закрытая модель не читает файлы/размеры/покрытие и не создаёт клетки. PostgreSQL остаётся источником данных, файлы сохраняются прежним production upload в S3/MinIO; клиентское состояние содержит только открытые панели, выбор, страницы и несохранённый ввод.

## Серверные чтения

- GET `/api/production/admin/assortment/directory/pattern-models`: страницы по 24, максимум 100; краткие поля модели, общее число файлов, число загруженных клеток актуальных активных размеров и требуемое число клеток. Поиск модели/кода лекала, конкретная модель, наличие активных/скрытых файлов и сортировки выполняются в SQL. Нет размеров, файлов или ORM агрегата в карточке.
- GET `.../directory/patterns`: независимые страницы полных кратких записей файлов с JOIN названия модели, кода/активности размера. Архивные размеры и файлы вне нынешнего диапазона остаются доступны в «Все файлы модели». Поиск по коду/имени/модели/размеру, model_id/size_id/active и сортировки — SQL.
- GET `.../directory/pattern-sizes`: поиск и страницы размеров конкретной модели, включая архивные; выбранный ID разрешается отдельно. Количество накопленных архивных размеров не ограничивает доступ первыми 100.
- GET `.../models/{id}/pattern-coverage`: одна модель и один размер, до шести значений каждой оси и двух вариантов рукава: максимум 36 клеток / 72 кнопки. Страницы ширины и длины независимы, доступны переходы назад/вперёд и прямой ввод номера. Последний участок включает только реально существующие точки. Отсутствующий диапазон возвращает пустую ось, а не выдуманный размер.
- GET `.../models/{id}/pattern-size/{size_id}`: контекст нового лекала, без коллекций. GET `.../patterns/{id}`: актуальная запись одного файла плюс его модель/размер. Ошибка, неполный ответ или чужая пара ID не открывают пустой редактор. Архивные модель/размер доступны для просмотра; их изменение требует предварительного восстановления активности.

Три списковых чтения используют по одному SELECT с limit+1, скалярные проекции и пустую ORM identity map. Покрытие — четыре SELECT (метаданные модели/размера, count и ограниченные файлы участка), редактор существующего файла — три. Ни один размер не превращается в полный массив всех точек в Python или браузере. Превышение/дублирование слотов не обрезается молча.

Шаг 2,00 см вынесен в `pattern_grid.py` и используется также действующей проверкой записи. Оси строятся от минимума размера; 50,25 → 52,25 — допустимая пара, 51,25 — нет. SQL считает в целых сотых сантиметра. Для деления явно сгруппирована разность: PostgreSQL cast numeric→integer округляет, а стандартный приоритет пользовательского SQLAlchemy оператора может изменить выражение. Это проверяется реальными SQLite/PostgreSQL данными.

Общее требуемое покрытие передаётся целой десятичной строкой, потому что несколько больших диапазонов превышают точность Number в JavaScript. UI использует BigInt только для счётчика. Пример 15 000 000 000 000 000 проверен точно; это счётчик тестовой геометрии, а не число созданных DOM элементов или измерение production нагрузки.

Cursor привязан к виду списка, фильтрам, сортировке и паре значение+ID. Геометрические страницы проверяют границы; при переданном expected_size_version изменение размера между переходами даёт 409 и требует обновить сетку. Это не транзакционный снимок всего каталога при конкурентных правках. Запись отдельно проверяет актуальные размеры и версию файла.

## Запись и загрузка файла

`get_pattern_for_update` обновляет ORM через populate_existing, поэтому ранее прочитанная запись в той же session не обходит expected_version. Модель и размер читаются с shared lock и актуальными значениями; подтверждённая версия лекала, принадлежность размера, активность, сетка, варианты рукава, уникальность слота и ready media проверяются сервером перед сохранением.

Редактор читает собственный контекст при открытии. Новый файл требует явного выбора модели/размера; отдельные поиски и страницы не сбрасывают ID. Смена выбора сбрасывает прежний незаписанный файловый контекст. Пустой поиск не подставляет первую модель или размер. Числовое поле показывает сохранённое значение, а ползунок следует той же сетке. Неверный шаг или отсутствующие диапазоны не позволяют отправить запись.

Payload выбирает разрешённые поля. Сантиметры отправляются точными строками; рост человека не смешивается с длиной изделия. Существующее самостоятельное name сохраняется при изменении code; автоматически созданное имя нового файла меняется вместе с его кодом. Сохраняются media_object_id и expected_version; read metadata не отправляется целиком.

Загрузка и запись имеют один синхронный lock. На это время поля, закрытие и фоновые действия экрана отключены. Ответ upload проверяется: без положительного ID файла нельзя показать подтверждённый успех. Отказ или неполный ответ сохраняет прежний файл/черновик, input очищается для повторного выбора того же файла. Повтор сохранения после failed PUT использует уже подтверждённый media ID и не загружает файл заново.

## Frontend и оболочки

- `AdminPatterns` владеет поиском/фильтрами и страницами кратких моделей, выбранным редактором и состоянием выполняемой команды.
- `PatternCoveragePanel` — дочерняя открытая модель: текущий размер/участок либо страницы всех файлов. Только активный вид читает данные; закрытие отменяет чтение. Прокрутка таблицы остаётся доступной с клавиатуры и на телефоне.
- `PatternEditor` — дочерний редактор одного файла/нового слота, его контекста, загрузки и черновика. Не оборачивает страницу.
- `patternDirectory.ts` проверяет DTO, координаты/шаг/размер окна и уникальные слоты. `patternEditor.ts` содержит чистые преобразования и whitelist payload. Ни UI, ни HTTP в преобразованиях формы нет.
- Общие `usePagedCatalog`, production sessionEpoch и `useAssortmentResource` сохраняют границы жизни запроса. Последний дополнен необязательной проверкой DTO и ключом обновления: остальные потребители сохраняют прежнее поведение. Нового Provider нет.

## Удаления и совместимость

Удалены последние production GET `/models` с фиксированными limit100/cursorNone и GET `/patterns` с массивом всех файлов. Старые list_patterns service/repository и frontend ReferencePage с числовым cursor также удалены. CRM GET `/api/crm/assortment/patterns` использует ту же ограниченную страницу под прежней CRM authority; body/параметры обновлены, старый массив не поддерживается. Проверены identity admin, отказ обычному identity и отказ без bearer даже при production cookie.

Все POST/PUT и прежние правила доступа/сохранения оставлены. Схема БД не менялась, head0072. Frontend/backend требуют согласованного выпуска; внешние потребители прежних read DTO должны перейти на новые контракты до переключения.

Полный backend: **1083 passed, 0 skipped**, 305,95 с на Python 3.12.12 со свежими PostgreSQL17 и настоящим MinIO; свои процессы, БД, файлы и приватная конфигурация удалены. Профильный native набор: 40/0skip. Ruff/format всех 655 Python файлов прошли.

Четыре новых контракта выполняются на SQLite/PostgreSQL: 130 моделей, 261 файл всего, у одной модели 132 файла и 130 размеров; включая архивный и вне-сеточный файл. Проверяются все сортировки/равные значения, cursor scopes, буквальный Unicode поиск, точные дробные минимумы, последняя страница, большой счётчик сверх 2^53, число SELECT/ORM, чужие ID и права. Настоящие PUT сохраняют имя/размеры/media, отклоняют плохой шаг/неизвестный файл/старую версию и проверяют stale identity map.

Полный frontend: **598 passed, 0 skipped**, lint без ошибок и production build/TypeScript с тремя release flags. Семь новых проверок read/write contracts: большой счётчик, окно/слоты, полный контекст и upload receipt, точная геометрия, сохранение имени/media/version, новый код и явные ID, серверные фильтры/no-store/cursor error. Прежние статические проверки читают выделенные части экрана и допускают форматирование строк.

Browser gate — настоящий standalone Next/Chromium с синтетическим HTTP API; SQL/права/реальные команды проверены отдельно выше. 130 моделей и размеров, 132 файла одной модели; нет prefetch закрытых моделей, поздний ответ закрытой сетки игнорируется, DOM ограничен 72 кнопками. Последние страницы обеих осей, geometry version conflict/обновление, failed/incomplete context без формы, архивные файлы и просмотр архивного размера, дробные 50,25×60,35/52,25×62,35, самостоятельное имя и media ID, failed/incomplete upload/повтор и failed PUT с тем же черновиком. Создание для модели130/размера2130, пустые поиски с сохранёнными ID, запрет шага51,25 и рукав по росту. Проверены 320/390/736/1280 px и короткий landscape736×390, горизонтальная прокрутка таблицы клавиатурой. Прежние сценарии кабинетов/пресетов/складов/техкарт и двух вкладок входят в тот же gate.

Это доказательство ограниченного вывода и корректности, не нагрузочный профиль больших production таблиц. Подсчёты SQL могут читать много строк; query plans/индексы на производственном объёме остаются отдельной проверкой. Другие справочники (включая категории моделей), крупные формы и общие ворота выпуска требуют дальнейшего аудита. Сохраняются прежние предупреждения CustomerMediaImage alt, fallback Alumni Sans SC и Starlette TestClient. Docker/Actions, опубликованный сайт, реальные устройства, backup/restore с внешними writers и настоящая оплата этим этапом не подтверждены.
