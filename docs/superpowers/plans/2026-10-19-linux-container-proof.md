# Релизные образы в настоящем Linux Docker

Статус: попытка завершена без полного успеха. Production не переключался.

## Изоляция и источник

Проверка использует доступный rootless Docker на сервере. До запуска записаны
ID, image ID, StartedAt и RestartCount всех14 существующих контейнеров;
их исходные health-статусы нормальны. Рабочие `.env`, тома и deployment metadata
не используются тестовым Compose. Фоновые платёжные/доставочные workers не
запускаются. Тестовая конфигурация создаётся случайно, хранится с правами0600
и не выводится в логи.

Снимок содержит1539 файлов текущей рабочей копии. Реальные `.env`, ключи,
локальные базы, node_modules и build-кеши исключены.162 совпадающих статических
файла скопированы из public существующего образа только на чтение. Для каждого
файла всего итогового снимка проверен SHA-256; добавочные файлы отсутствуют.
Передано1.92 МБ недостающих данных вместо59.77 МБ полного сжатого архива.

Оба образа собираются последовательно из текущих Dockerfile и lock-файлов,
без замены рецепта сборки и без пропуска TypeScript. Образы получают отдельные
тестовые теги, в registry не публикуются.

## Ресурсы

Отдельный BuildKit builder:768 MiB, swap0, CPU0.5. Проверены не только параметры
Docker, но и фактические memory.max/memory.swap.max/cpu.max. Лимиты задаёт
[docker-container driver](https://docs.docker.com/build/builders/drivers/docker-container/).
Builder не становится default и удаляется до запуска runtime-проекта.

Тестовый Compose основан на неизменённом серверном descriptor; дополнительный
временный JSON ограничивает память/CPU и отключает restart только его сервисов.
Сумма memory limits пяти постоянных тестовых сервисов864 MiB: PostgreSQL128,
Redis32, MinIO320, API192, frontend192. Одноразовые jobs имеют отдельные лимиты.
Тест не измеряет допустимую производственную нагрузку или время сборки в CI.

## Что проверяется

`deploy/scripts/smoke-containers.py`: новая PostgreSQL, Redis и MinIO; init роли
и buckets; Alembic upgrade; API/frontend из собранных Linux-образов.
UID10001 у приложений, отдельная роль PostgreSQL без superuser/create прав.
Readiness, публичные пустые страницы каталога/людей/сообществ через API и rewrite,
401 приватных API,404 удалённых settings, запрет приватных изображений в Next
optimizer и доступность публичного PNG. Серверный HTML главной/каталога и все
связанные JS/CSS. Повторный Alembic head и удаление собственного проекта/томов.

## Результат

Backend-образ собран и загружен в rootless Docker. Frontend не завершил Next
compile до тайм-аута1800с при указанных лимитах. Общее время попытки2997с.
Сообщение `context canceled` следует за тайм-аутом harness; это не найденная
ошибка TypeScript. В последнем наблюдении cgroup OOM/oom_kill равны0. Нехватка
ресурсов возможна, но её нельзя считать доказанной единственной причиной.
Полный smoke с Next и публикация образов не состоялись.

Отдельная попытка запуска backend из того же образа завершилась на `Compose run`
до HTTP. В прежнем сообщении не было имени job, поэтому точный упавший job
по этому логу установить нельзя. Инициализации роли БД и MinIO затем отдельно
прошли в настоящем Docker. Найдена и воспроизведена гарантированно невалидная
конфигурация миграций: env-файл включал каталог, но не MinIO, а сервис migrate
заменяет общую environment mapping. Исправление и границы проверки описаны
[в этапе проверки корзины](2026-10-19-container-cart-gate.md).

Runtime приложений, Dockerfile, зависимости, миграции и серверный Compose не
менялись после снимка. Локально обновлены deploy-скрипты/проверки и документация.
Новый порядок backup отдельно проверен82 Bash/backup/verifier тестами, расширенный
smoke —28 unit проверками. Это не успешный полный Docker gate.

После попыток проверены те же14 исходных контейнеров: ID, image ID, StartedAt
и RestartCount совпадают. Собственные контейнеры, тома, builder, теги образов и
приватные runtime-конфиги удалены; временная серверная папка также удалена
после сохранения локальных доказательств. Ошибок очистки не зафиксировано.

Этот smoke не является переключением рабочего сайта, запуском GitHub Actions,
переносом реальных данных, проверкой старого образа с новой схемой, restore
производственного архива, платёжным E2E или телефонным замером LCP. Общий релиз
продолжается; stage/commit/push/deploy отсутствуют.
