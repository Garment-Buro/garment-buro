# Настоящий rootless release с публичным окном обслуживания

20.10.2026 неизменённые release, backup, verifier и public-maintenance CLI
прошли совместный прогон на отдельном Linux/rootless Docker 29.9.1/Compose 5.6.0
и настоящем Nginx под uid1000. Публичные HTTPS-входы тестовые и loopback-only,
сертификат проверяется. Application images — прежний проверенный amd64 runtime
под binfmt: совпали 1371 хеш runtime-исходников. Два candidate label/config ID
отличаются; бизнес-код в них одинаков. Registry локальный, providers отключены,
workers — sleepers. Рабочие БД/S3 и серверные настройки не читались.

Четыре неизменённых CLI-сценария: ошибка storage-init до миграций 41;
нездоровый worker после HTTP нового API/Next 1; успех 0; ошибка открытия 78.
Непрерывные GET страницы/корзины и PUT корзины проверяли настоящий публичный
Nginx. Пока API остановлен и пока новый image уже работает до commit,
наблюдались 503, no-store, Retry-After 60 и подпись среды. Ранний сбой сохраняет
исходные IDs/images/environment; поздний восстанавливает только прежний
running set. Setup jobs не перезапускаются, инфраструктурные IDs совпадают.
Созданы 4 настоящих backup-комплекта, каждый verifier подтвердил 5 файлов.

В последнем сценарии metadata уже зафиксировала новую версию. Первый HTTPS
вход принял реальную запись корзины с серверной ценой 1580; второй origin
преднамеренно ответил неверным состоянием. Helper снова закрыл трафик,
новые images и metadata сохранились, публичная запись не потерялась.
После исправления fixture владелец блокировки повторно открыл трафик.
Публичные главная/каталог, корзина и paginated история доступны; API/Next
сохранили 10 000 заказов, избранное, принятый состав, файлы/версии/политики MinIO.

Первая попытка остановилась на default fastcgi temp path пакета Nginx,
недоступном uid1000; временные пути перенесены внутрь fixture. Все контейнеры
и volumes первой попытки были очищены перед повтором. Репозиторий при этом
не менялся во время прогона. Все 1702 исходных хеша совпали до/после него.
Та же проблема абсолютных temp paths подтверждена в отдельной Linux-копии
двух repository verifiers. Точные исправленные копии прошли privacy 8/129 с
negative controls и maintenance 5 на uid1000 до применения правок в репозитории.
После завершения release исправлены только пути fastcgi/uwsgi/scgi этих двух
утилит; runtime приложения и release/controller остались прежними.
Собственные Nginx, контейнеры, volumes, сети, VM/диски и CLI config удалены.

Это доказательство lifecycle и публичного барьера, не работа реальных
провайдеров и не совместимость старого исторического ASGI с новой схемой.
Последнее ранее проверено как отказ старого образа и checkpoint recovery
со своей границей потери последующих записей. Новый полный suite после gate,
реальный CI, рабочий объём и окно восстановления остаются открытыми.
Публикации, commit/push и развёртывания на рабочем сервере не было.
