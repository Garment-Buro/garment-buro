# Сборка образов и доступность хранилища

Статус: оба образа приложения собраны; полный запуск ещё не подтверждён.
Production не переключён; stage, commit, push и deploy не выполнялись.

## Что проверено

Использован неизменяемый снимок **1547 файлов** frontend/backend/deploy,
сверенный по SHA-256. Архив не содержит приватных env, ключей, БД, uploads,
node_modules или .next. Приложения собирались настоящими Dockerfile и lock.

На отдельной локальной Linux/aarch64 VM собраны оба образа **linux/amd64**
через binfmt-эмуляцию. Первый builder с 2 GiB завершил backend, но frontend
получил SIGKILL и `ResourceExhausted: cannot allocate memory`.
Вторая попытка: VM 6 GiB, 2 CPU; builder 4 GiB, 2 CPU, swap 0.
Настройки Docker и реальные cgroup-лимиты сверены.
Frontend с Next 16.3.8/Turbopack скомпилирован, TypeScript и prerender прошли;
standalone-образ успешно экспортирован. Компиляция заняла 49 с, шаг
`npm run build` — 100,5 с. Все эти времена относятся к эмуляции, а не к
скорости страниц или требованиям production-сборки на native amd64.

Сборки завершены за 242 с вместе с попыткой runtime:

## Что остановило чистый запуск

`Compose up` инфраструктуры завершился ошибкой до HTTP-проверок.
Отдельные попытки скачать указанные в Compose образы дали:

| Источник | Результат 19 октября 2026 |
| --- | --- |
| Docker Hub: `minio/minio:RELEASE.2025-07-23T15-54-02Z` | pull access denied |
| Docker Hub: `minio/mc:RELEASE.2025-08-13T08-35-41Z` | pull access denied |
| Quay: те же версии `minio/minio` и `minio/mc` | 401 Unauthorized |
| Официальные архивные sha256sum этих версий, amd64 и arm64 | 410 Gone |
| PostgreSQL 17 и Redis 7 из Docker Hub | Образы скачаны |

Это самостоятельно воспроизведённый блокер холодной установки. Общая ошибка
smoke не сохраняет stderr Compose, поэтому точный внутренний первый отказ
не устанавливался по её сообщению. Успешный прежний запуск с уже скачанными
образами не подтверждает доступность этих образов на новом сервере или в CI.

Проблемные ссылки находятся в local/server Compose и backend job CI.
Простой переход на Quay не устраняет отказ. Случайное стороннее зеркало и
новая версия S3-хранилища не подставлялись; данные и формат хранения не менялись.

Официальные репозитории [MinIO](https://github.com/minio/minio) и
[mc](https://github.com/minio/mc) архивированы. README MinIO прямо сообщает,
что проект больше не поддерживается, и описывает сборку из исходников.
Для воспроизводимого выпуска нужен отдельный шаг: выбрать поддерживаемую
поставку S3 либо собирать и хранить проверенные образы из зафиксированных
исходников. Последний вариант сохраняет текущий интерфейс, но сам по себе
не возвращает upstream-поддержку. Публикации образов этим этапом нет.

## Граница результата

Сборка приложения подтверждена; init/миграции и реальные HTTP через Next
в этой попытке **не пройдены**. Подтверждённый предыдущий backend-only запуск
с корзиной после restart без Redis сохраняет свой отдельный статус.
Синтетические конфиги, контейнеры, volumes, сети, builder и теги обеих локальных
попыток удалены; фактический postflight проверяет отсутствие своих ресурсов.
Временная VM и её диски удалены после postflight. CLI-инструменты Docker/Colima,
установленные для проверки, остаются на компьютере без фонового сервиса.

Общий релиз остаётся в работе: чистый storage/bootstrap, актуальный CI,
restore/rollback, совместимость прежнего образа и публичные сценарии выпуска.
