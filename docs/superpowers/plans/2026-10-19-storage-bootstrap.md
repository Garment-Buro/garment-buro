# Единая настройка S3-бакетов

Статус: реализована и проверена отдельно; весь релиз ещё не завершён.
Production и данные не переключались; stage/commit/push/deploy отсутствуют.

## Изменение

Local/server Compose больше не скачивают `minio/mc` для настройки бакетов.
Оба вызывают `python -m scripts.bootstrap_storage` в том же backend-образе,
который выпускается с приложением. Серверный init получает только endpoint,
S3-ключи и три имени бакетов; PostgreSQL/JWT и полный application env ему не нужны.
Имя сервиса `minio-init` сохраняет действующий порядок выпуска и workers.

Правила находятся в `backend/app/integrations/storage_bootstrap.py`.
Команда проверяет имена и запрещает совпадение публичного бакета с частными
до первого запроса. Создаёт отсутствующие бакеты, не меняет объекты.
Сначала снимает и проверяет политики обоих частных бакетов, затем разрешает
анонимный GetObject для media. Анонимные ListBucket и запись не разрешены.
Это намеренно уже прежнего `mc anonymous download`: карточки получают список
из API/БД, а не через анонимный ListBucket.

Повторный запуск сохраняет файлы. Ошибка чтения политики, отказ доступа либо
неудалённая частная политика останавливают команду до открытия media.
Это явная команда оператора; API startup не создаёт бакеты и не меняет ACL.
CLI сообщает JSON-событие и класс ошибки без текста SDK с возможными ключами.
Connect/read ограничены 5/15 с, retries — 2. `--help` не обращается к S3.
Используется закреплённый Python SDK; новых пакетов и lock-изменений нет.
Неиспользуемый `NEXT_PUBLIC_USE_MOCK_DATA` убран и из local Compose.

## Проверка

Общий целевой набор **89 passed, 0 skipped, 34,92 с**: 17 новых unit,
32 smoke и 40 release-проверок. Новые unit покрывают сохранность объектов, повторный запуск, разные
публичные/частные имена, ошибочные политики, отказ S3 и безопасные CLI-ошибки.
Настоящий Docker Compose 5.6.0 проверил обе конфигурации на синтетическом env;
приватные файлы удалены. Ruff check/format прошли.

Настоящий native Linux MinIO запущен со свежим собственным volume,
loopback-портом, случайными ключами, лимитом 320 MiB/CPU 0,35.
SDK через SSH-туннель проверил текущий код: создание отсутствующего media,
исправление намеренно публичных CRM/projects, сохранность байтов после
повторного init, публичный GET media и 403 для частного GET, анонимных
ListBucket и PUT. Проверка прошла без пропусков за 8–9 с.
После добавления HTTP timeout она повторена на новом свежем volume.
Оба собственных контейнера, volumes, конфиги и серверные папки удалены;
исходные 14 контейнеров совпали по ID/image/StartedAt/restarts.

## Граница результата

Использован уже скачанный серверный образ; холодная скачиваемость сервера
этим не исправлена. Доступность `minio/mc` больше не требуется, но исходный
`minio/minio` ещё указан в local/server Compose и backend CI.
Выбор поддерживаемого S3 и размещения файлов остаётся следующим шагом.
Перенос пользовательских файлов и изменение provider не выполнялись.

Полные backend 1299 и frontend 626 относятся к предыдущему этапу.
Новая проверка backend-образа с этим init и полный HTTP через Next ещё нужны.
[Прошлая сборка обоих образов](2026-10-19-container-build-storage.md)
проверяла снимок до этого изменения.
