# Складские справочники: фурнитура, категории и упаковка

Этап локального рефакторинга. Основное управление товарами остаётся в производстве → «Пресеты», как выбрал пользователь. Старые страницы товаров перенаправляют туда. Складские справочники обслуживают производственные модели и не создают ещё один редактор товаров. Stage/commit/push/deploy не выполнялись.

## Проблема и новое поведение

Экраны фурнитуры и коробок загружали полные массивы складских позиций и правил, а подписи и выбор производственной модели зависели от первых 100 моделей. Фильтры применялись к этим массивам в браузере. Для счётчика применимости фурнитуры загружались все связанные model_ids. Вместимость выбранной коробки искалась в текущем массиве коробок.

Теперь пять независимых списков читаются страницами по 24: фурнитура, её категории, нормативы расхода, коробки и правила упаковки. Поиск, складские фильтры и сортировки выполняются в SQL; cursor включает вид справочника, фильтры и пару значение сортировки + ID. Максимальный limit — 100. Ошибка продолжения сохраняет уже прочитанные записи; недействительный cursor требует явного обновления.

## Серверные границы

- `stock_directory_router` — тонкий production adapter с прежним `require_system_admin`. Права production manager, покупателя и владельца коллекции не расширены.
- `stock_directory_schemas → stock_directory_service → stock_directory_repository` — контракты, cursor orchestration и SQL-проекции в CRM. Общая обработка no-store/ошибки cursor вынесена в `directory_api`, используется также моделями и тканями.
- GET `/api/production/admin/assortment/directory/accessories` возвращает category_name и model_count из SQL вместо гидратации связей и передачи model_ids. Категория, активность, минимум остатка и сортировки ограничивают запрос на сервере.
- GET `.../directory/boxes` содержит полные редактируемые габариты, цену и вместимость, но не связанные коллекции. GET `.../directory/accessory-categories` содержит также описание и версию для безопасного редактирования категории.
- GET `.../directory/accessory-requirements` соединяет названия модели/фурнитуры. Порядок сохраняется: свежие ID первыми. GET `.../directory/packaging-rules` соединяет названия модели/коробки и её box_capacity; порядок — priority, затем ID. Оба списка имеют собственный поиск и продолжение.
- GET `.../directory/selected` поддерживает модели, ткани, фурнитуру, коробки и категории. Максимум 50 ID; существующая скрытая запись разрешается отдельно от страницы вариантов. Коробка включает свою max_items.

Каждая из пяти страниц — один SELECT, limit+1, без наполнения ORM identity map. Decimal для цены/габаритов не заменяется нулями. Сортировки устойчивы при одинаковых значениях. Буквальные `%`, `_`, обратный слеш и Unicode поиск проверены отдельно на PostgreSQL и SQLite.

## Frontend и оболочки

`AdminAccessories` использует независимые `useAccessoryDirectory`, `useAccessoryCategories`, `useAccessoryRequirements`; `AdminBoxes` — `useBoxDirectory` и `usePackagingRules`. Общий controller — прежний `usePagedCatalog`, привязанный к виду запроса, фильтрам и production sessionEpoch. Никакого нового Provider или оборачивания страницы нет.

`ReferencePicker` — дочерний UI одиночного выбора пяти видов записей. Подтверждённый ID/название читаются отдельно, поиск и продолжение меняют только варианты. Категория фильтра сохраняет выбранный ID/название при независимом поиске категорий; переименование обновляет эту подпись. Новый норматив требует явного выбора модели.

У правила упаковки box_capacity приходит вместе с записью; изменение списка не убирает ограничение. Явный выбор другой коробки берёт её вместимость из ответа и ограничивает max_items. Сервер остаётся окончательной проверкой вместимости и возвращает 409 при конфликте.

На время записи редактор и фоновые действия этого складского экрана отключены; синхронный lock предотвращает повторный submit. Ошибка возвращает управление с тем же черновиком и expected_version. Расход фурнитуры допускает шаг 0,001, как серверный контракт. Изменение только названия сохраняет стоимость, остаток, фото и размеры коробки; payload содержит разрешённые поля, а не read DTO целиком.

## Удаления и совместимость

Пять старых production GET `/accessories`, `/boxes`, `/accessory-categories`, `/accessory-requirements`, `/packaging-rules` удалены после переноса потребителей. POST/PUT и их проверки версий сохранены. На момент этапа старый production GET `/models` требовался лекалам и техкартам; последующим [этапом техкарт](2026-10-18-tech-card-directory.md) их список/редактор перенесены. Старое чтение моделей осталось только у лекал. Большие формы и проверка query plans/индексов остаются в работе.

Схема БД не менялась; Alembic head остаётся 0072. Новые frontend/backend требуют согласованного выпуска. Старые массивы и неполные DTO не выдаются за правильный новый ответ.

## Проверки

Полный backend: **1067 passed, 0 skipped**, 301,81 с на Python 3.12.12 с отдельным PostgreSQL 17 и настоящим MinIO. Процессы, данные и приватная тестовая конфигурация удалены. Новый контрактный набор исполняется на SQLite и PostgreSQL: по 130 записей каждого вида, все сортировки/совпадающие значения, фильтры и курсоры, Unicode/literal поиск, SQL count=130 без model_ids, один SELECT/пустая ORM identity map. Настоящие PUT сохраняют дробные значения и проверяют expected_version/вместимость коробки. Guest/identity-only получают 401, production manager — 403. Ruff/format всех 644 Python файлов прошли.

Полный frontend: **585 passed, 0 skipped**. Production build/TypeScript и lint без ошибок. Пять новых исполняемых проверок read contracts: отсутствие model_ids, полные размеры/цена, joined названия/вместимость, фильтры/no-store/cursor errors, выбранная коробка с правильным ID/capacity. Прежняя проверка текстовой подсказки допускает перенос строки после форматирования исходника.

Browser gate использует настоящий standalone Next/Chromium с синтетическим HTTP backend; серверные гарантии проверены отдельно выше. По 130 записей пяти списков; отказ следующей страницы/повтор, invalid cursor/обновление, независимый фильтр категории и его переименование. Выбранные ID 130 не теряются при пустом поиске. Отложенный failed PUT отключает поле/закрытие/создание на фоне, затем сохраняет черновик; повтор отправляет тот же payload. Стоимость 12,34 ₽, остаток 25, расход 1,234 и габариты 30,25 × 20,35 × 10,45 сохраняются. У правила коробка 130 имеет вместимость 7; выбор коробки 129 уменьшает максимум с 3 до 2, пустой поиск его не сбрасывает. Новые формы проверены на 320/390/736/1280 px и коротком landscape 736×390. Прежние сценарии пресетов, кабинетов, реквизитов, справочников тканей и двух производственных вкладок входят в тот же gate.

Это не нагрузочный замер большого production справочника и не доказательство готовности релиза. Сохраняются прежние предупреждения CustomerMediaImage alt, fallback шрифта Alumni Sans SC и Starlette test client. Docker/Actions, опубликованный сайт, реальные устройства, backup/restore с внешними writers, совместимость прежнего образа и реальная оплата этим этапом не подтверждены.
