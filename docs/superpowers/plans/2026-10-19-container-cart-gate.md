# Проверка постоянной корзины в релизном образе

Статус: проверяющий код расширен; полный контейнерный результат ещё не получен.

Последующий этап подтвердил текущий backend в Linux, включая сохранение
корзины после перезапуска с Redis exited. Исправлены запуск зависимостей через
Compose start и смена случайного порта. Полный HTTP через Next ещё впереди.
[Актуальное подтверждение](2026-10-19-backend-runtime.md).
Ниже сохранён результат первоначального этапа.

## Изменение

Прежний smoke проверял пустые публичные списки, страницы и зависимости, но не
включал CARTS_V2_ENABLED. Теперь создаёт один настоящий товар в свежей БД,
передаёт через HTTP заведомо неверную preview-цену0.01 и требует серверную цену
конструктора1500+80=1580, количество2 и customization. Точный повтор операции
должен вернуть тот же снимок; новая операция со старой ревизией —409.
Все ответы требуют no-store. После остановки API и Redis запускается только
API; обе HTTP-границы должны вернуть прежний снимок.

Случайная capability корзины остаётся в памяти/HTTP, не попадает в CLI или
собственные сообщения об ошибке. Ошибка Compose теперь называет известный init
job без вывода stderr, конфигурации или паролей. Сервисные флаги MinIO и адрес
minio:9000 включены в синтетический env-файл также для migrate.

Формула80 ₽, код приложений, Dockerfile, зависимости и Compose не изменялись.

## Подтверждено

- 28 unit/0skip,8.75с: настоящий HTTP transport JSON PUT, запрет кеширования,
маскирование capability, флаги, изоляция, ошибки и cleanup, сигналы и безопасное
имя job. Ожидаемые регрессии воспроизведены до исправления.
- 32 профильных теста формулы и cart API/ревизий прошли; это native-набор.
- Настоящий Docker Compose разрешил окружение сервиса migrate до/после исправления.
Из него сохранены только разрешённые публичные флаги/endpoint. Настоящий native
Settings отверг прежнее окружение из-за MINIO_ENABLED и принял исправленное.
Это совместная проверка descriptor и валидатора, а не выполнение нового image.
- Отдельные database-role-init и minio-init прошли на свежих Docker volumes.
- Ruff и format двух изменённых Python-файлов прошли.
- Карта: 21 offline-набор, 666 валидных ссылок на исходники, 320/390/736 px;
без сетевых запросов, ошибок JavaScript и переполнения. Inline997671 байт.
Раздел «Контейнеры · проверка запуска» показывает неуспех полного gate и границы
отдельных подтверждений. Самостоятельная HTML-копия обновлена.

## Что не подтверждено

Попытка полного Linux gate: backend собран, frontend остановлен тайм-аутом30мин
при768MiB/CPU0.5. Последующая попытка backend-only остановилась на Compose run,
не дойдя до записи корзины. Инициализация затем изолированно прошла; обнаруженная
ошибка настроек исправлена, но повторного запуска актуального backend-образа
после исправления ещё нет. Тест сохранения корзины при перезапуске добавлен в CI,
его успешное выполнение в образе пока не заявляется.

Перед следующей попыткой нужен пригодный executor для frontend build и новая
проверка обоих образов текущим smoke. Нельзя трактовать native build, unit-тесты
или успешный init как подтверждение полного Docker/CI/production.

Все14 исходных контейнеров остались неизменны. Собственные ресурсы тестов и
синтетические конфиги удалены. Stage/commit/push/deploy отсутствуют; общий релиз
продолжается. [Снимок, лимиты и результаты](2026-10-19-linux-container-proof.md).
