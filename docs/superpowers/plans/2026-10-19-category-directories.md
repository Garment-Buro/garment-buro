# Категории моделей и пресетов без полных массивов

Статус: локальная реализация и проверки этого этапа завершены. Общий релиз остаётся в работе. Основной редактор товаров — производство → «Пресеты».

## Проблема и результат

`AdminModels` загружал все категории моделей, строил из них карточки, фильтр и варианты формы, а затем искал в этом массиве названия категорий для моделей. `AdminProducts` и редактор пресета отдельно читали целиком категории товаров, включая полные описания. Ошибка списка могла мешать открытию товара. Категории редактировались по версии из старого списка; большие экраны содержали собственные формы и обработчики записи.

Теперь два вида категорий получают независимые краткие страницы по 24, максимум100, с поиском, видимостью и непрозрачным курсором. Редактор одной категории отдельно получает актуальную запись. Название категории в карточке модели приходит из JOIN и не зависит от страницы справочника. Фильтр и форма сохраняют выбранный ID при поиске и догрузке.

## Сервер и данные

- GET `/api/production/admin/assortment/directory/categories/{kind}`, где kind — `model-categories` либо `product-categories`. Карточка содержит id/code/name/is_active/version/item_count; code товара — его slug. В списке нет description, коллекции моделей/товаров и ORM объектов. Счётчик считает все связанные записи в БД, включая скрытые, а не только уже загруженную страницу.
- Поиск по имени/коду, видимость и сортировки выполняются в SQL. Общий keyset использует значение+ID; курсор привязан к виду категорий и фильтрам. Неизвестные/лишние параметры отвергаются. Страница, одна деталь и выбор по ID требуют по одному SELECT.
- GET `.../model-categories/{id}` и `.../product-categories/{id}` возвращают свежую проекцию одной категории. Полное описание товара читается только для этой формы. Существующий `/directory/selected` поддерживает оба вида и не ограничивает выбор первой страницей, поиском или активностью.
- Старые production GET полных категорий удалены. POST/PUT остаются на прежних адресах под прежними system-admin правами и production cookie. Canonical GET `/api/product-categories` также возвращает ограниченную страницу под прежним `require_catalog_writer`; это не публичный каталог.
- Удалены неиспользуемый полный метод категорий моделей в reference repository, старые `ReferenceDirectoryService.categories`, `CatalogService.list_categories`, `CatalogRepository.list_categories`, старый DTO `ModelCategoryCard` и общий GET-handler с `CatalogResponseMapper`.
- Оба category writer читают заблокированную запись с `populate_existing`: объект, ранее загруженный той же ORM session, не обходит expected_version. Имена, служебный код модели, адрес/описание товара, видимость и версии сохраняются прежними командами; тарифы и размеры здесь не меняются.
- Миграция `20261019_0074` добавляет два индекса Unicode имя+ID. Нативный план на 20 000 категорий каждого вида проверяет переход после19 000-й позиции: индекс читает25 записей, включая строку продолжения, также при PREPARE/EXPLAIN EXECUTE с generic plan. Это проверка сортировки по имени, не обещание одинаковой стоимости всех фильтров и сортировок.
- Миграция и ORM совпадают. Двукратный downgrade/upgrade сохраняет модели, категории обоих видов, описания, версии и timestamps. Данные остаются в PostgreSQL. Новый Redis-кэш не требуется; TTL/инвалидацию кэширования этим этапом не вводили.

## Интерфейс и оболочки

`ProductionTerminal` и workspace с ключом производственной сессии остаются оболочкой. `CategoryDirectory`, `CategoryFilter`, `CategoryEditor` и `ReferencePicker` — дочерние блоки. `useCategoryDirectory` и `useSelectedReference` — hooks, без новых Provider.

`CategoryDirectory` отвечает за короткие карточки, поиск, видимость, продолжение и локальный отказ. `CategoryFilter` открывает выбор по запросу и независимо обновляет название выбранного ID, в том числе после переименования. `useSelectedReference` выделяет общий жизненный цикл выбранной записи из `ReferencePicker`: kind/ID/sessionEpoch/refresh key и AbortController защищают от поздних ответов. Результаты страниц не меняют выбранный ID.

`CategoryEditor` разделяет загрузку актуального источника и состояние формы. Для модели поля имени/видимости, для товара — имени/slug/описания/видимости; общие загрузка, диалог и защита записи не дублируются в двух больших экранах. Неполный ответ, другой ID или ошибка не открывают пустую форму. Версия из страницы не используется для записи. Служебный код модели не передаётся как редактируемое поле; переименование товара не пересоздаёт старый slug. Прежняя транслитерация новых адресов сохранена.

Запись блокирует всю форму, закрытие и фоновые действия; ref-guard останавливает повторный submit до перерендера. Отказ сохраняет ввод. При409 можно явно загрузить актуальную категорию с заменой черновика; автоматического обновления версии/перезаписи нет. Подтверждённая запись закрывается независимо от результата последующего списка.

Редактор пресета открывает основной detail самостоятельно, без Promise.all с полным массивом категорий. Его категория выбирается отдельными страницами, а сохранённая запись — по ID. UI редактора явно использует production client, согласуясь с выбранным основным кабинетом. Низкоуровневый клиент HTTP отдельно проверяется для identity/production авторизации. Альтернативного старого редактора страниц это не возвращает.

Для нового назначения модели/пресету показываются активные категории, как требует сервер. Уже сохранённая скрытая категория остаётся видимой с прежним ID: её можно восстановить или явно выбрать другую. Ошибка/пустой поиск не назначают первую категорию автоматически.
