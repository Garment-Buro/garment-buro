# Фото для карточек людей

Статус: локальный этап; весь рефакторинг релиза продолжается.

## Проблема и результат

Главная и каталог людей использовали полное нормализованное фото профиля:
lossless WebP до512 px, хотя портрет карточки занимает96–161 CSS px.
Карточки теперь запрашивают отдельный фиксированный `/preview` до320 px,
WebP quality85. Страница профиля и личный редактор сохраняют прежний исходник.
Общий обработчик изображений конструктора не менялся: качество принтов
и проектных изображений сохраняется.

## Поток и границы

`ServicePersonCard → publicAvatarHref(person, 'card') → PublicAvatar →
GET /api/people/{slug}/avatar/{media_id}/preview → AvatarService.read →
PostgreSQL policy → приватный MinIO → размер/SHA-256 → worker thread → WebP`.

Источник до512 px уже проверен при загрузке. Preview не увеличивает малые
фотографии, сохраняет альфа-канал и не переносит EXIF/ICC. Некорректный источник
отклоняется. Новый endpoint не принимает произвольные размеры и quality.
Существующие фотографии работают без повторной загрузки. Нового Provider,
миграции, DB-полей, постоянных производных файлов и кеша нет.

Публичные фото по-прежнему читаются напрямую через API: no-store/nosniff,
без redirect в MinIO или Next image optimizer. На каждый запрос проверяются
публикация, активный аккаунт и актуальное прикреплённое фото. Снятие публикации,
замена, удаление фото или блокировка/удаление аккаунта закрывает новый запрос.
Уже полученные клиентом байты отозвать невозможно.

Оптимизация уменьшает передачу к браузеру. Она не уменьшает размер чтения
из MinIO: полный канонический объект всё ещё читается и проверяется каждый раз.
Preview добавляет ограниченное кодирование до512→320 px вне event loop.
Постоянные производные файлы потребовали бы отдельного жизненного цикла
создания/очистки; в этом этапе он не добавлен.
