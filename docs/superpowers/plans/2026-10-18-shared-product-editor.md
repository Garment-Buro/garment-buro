# Один редактор товара для двух способов входа

18 октября. Этап общего рефакторинга выполнен локально. Stage/commit/push/deploy
не выполнялись; общий релиз ещё открыт.

Следующий этап добавляет защиту версии товара: [product-version](2026-10-18-product-version.md).
Перечень оставшихся задач ниже относится к моменту завершения общей формы.

## Результат

- `ProductEditorDialog` — одна форма, `useCatalogProductEditor` — её контроллер.
  Production `AdminProducts` открывает её с cookie-клиентом, старые прямые
  `/admin/products/new` и `/admin/products/{id}/edit` — с identity Bearer клиентом.
  Менеджера не перенаправляем в кабинет, требующий другого системного кода.
  Новых Provider и отдельного браузерного справочника нет.
- Общие media/варианты покрывают основные фото, обратную сторону, обложку,
  используемые галереи конструктора, media варианта, ширину/длину изделия,
  вес/габариты доставки, описание/состав/видимость и реальные refs. Старые
  video/poster/size-chart поля сохраняются при записи, но ненужные прежние
  блоки лендинга в интерфейс не переносятся.
- Существующий товар без garment_model_id сохраняет физический запас и свои
  варианты. Production PUT использует общий ProductWriteRequest; новый POST
  пресета по-прежнему требует производственную модель. Вычисленная доступность
  не заменяет raw stock; вариантные ID/SKU сохраняет общий writer.
- Выбор модели/ткани читает страницы24 с поиском и продолжением; выбранная
  модель и ткани читаются отдельно по их настоящим ID. Поэтому строка130 не
  пропадает, когда первый экран содержит только1–24. Ткани поиска ограничены
  требованиями выбранной модели. Ответ не включает цены закупки, balances
  или все product_ids модели.
- `/api/catalog-editor/*` проверяет catalog.write. Production
  `/api/production/admin/assortment/editor-options/*` проверяет системного
  администратора. Оба используют один reader. Query/ID/limit валидируются,
  no-store; frontend reads имеют10-секундный deadline и отмену.
- Удалены прежние8 компонентов формы и больше не используемый shared Input,
  старые useAdminProductForm/useMediaUpload/variantOptionsStore, frontend
  options API/тип/normalizer, productForm mapper/payload. Новых версий этих
  компонентов с V2/V3 не добавлено.
- Удалены backend GET/PUT `/api/options`, PUT `/api/variants/{id}` и их отдельные
  writer/service/repository. Изменение варианта идёт через общую операцию
  товара с ID. Схема старых options оставлена только явному offline импорту;
  исторические документы, ревизии и fingerprints из БД не удаляются.

## Что остаётся в общем релизе

- Product version/CAS: parent lock сериализует writer, но не ловит устаревшую
  открытую форму. Это отдельная следующая задача целостности.
- Список лендингов/membership в production всё ещё unbounded; карточки товаров
  ещё несут полный массив variant references, хотя editor теперь независим.
- Остальные справочники производства вне этого picker требуют своего аудита
  пагинации. Здесь исправлен выбор модели/ткани в общей форме товара.
- Контейнеры/Actions, предыдущий образ/схема, реальный телефон, backup с
  внешними писателями и полный публичный платёжный E2E ещё не подтверждены.

Дальнейшее масштабирование чтения лендингов и карточек выполнено в
[следующем этапе](2026-10-18-admin-landing-directory.md). Старый перечень
незавершённых задач выше описывает момент этого этапа.
