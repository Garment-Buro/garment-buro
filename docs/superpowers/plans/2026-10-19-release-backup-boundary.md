# Backup в непрерывном окне обслуживания

Статус: локальная реализация и проверки завершены; рабочий сайт не переключён.

## Проблема

Скрипт выпуска сначала делал backup. Его EXIT handler возвращал прежние
приложения и workers, а скрипт выпуска останавливал их позднее. Архив был
согласованным внутри себя, но не содержал возможные записи между его окончанием
и миграцией. Проверка порядка остановки только при Alembic этого не обнаруживала.

## Изменение

Скрипт сначала проверяет прежний набор сервисов и адреса проб. Затем устанавливает
обработчик восстановления, останавливает прежние workers и API/frontend,
проверяет отсутствие работающих writers и запускает обычный backup. Backup видит
только инфраструктуру: останавливает MinIO на время копирования и возвращает
только MinIO. Приложения остаются остановленными до запуска кандидата.

После проверки архива и сохранения его точного пути выполняются bucket/role init,
повторная проверка writers и миграция. Прежняя конфигурация и тома остаются
источником архива. Дополнительного режима backup, флага или протокола передачи
состояния между скриптами нет. Ручной backup по-прежнему возвращает именно свой
исходный запущенный набор.

Ошибка архива, проверки архива или init возвращает прежние контейнеры через
start, без пересоздания их окружения. INT/TERM во время backup также проверены.
Неожиданный возврат writer после backup блокирует миграцию. Прежние правила
возврата после запуска кандидата и запрет автоматического downgrade сохранены.

## Проверки

Три регрессии сначала упали на прежнем скрипте: работающие приложения при backup,
повреждённый архив при работающих writers и незамеченный возобновлённый writer.
После исправления весь набор: **82 passed, 0 skipped, 40.39 с** — 40 release
и 42 backup/verifier. Настоящий Bash 3.2; Docker/Linux transport эмулируется.
Архивирование, SQLite backup, SHA-256 и kernel flock выполняются реально.
Новые backup-проверки подтверждают возврат только MinIO при успехе и ошибке dump,
когда приложения остановлены родительским выпуском. Окружение fixtures очищено
от случайных пользовательских переменных.

Ruff, format700, Bash syntax и scoped diff check прошли. Изменения исходников
относительно контейнерного снимка перечислены и сверены отдельно по SHA-256.
Карта обновлена:20 offline suites,666 корректных ссылок,320/390/736 px,
без HTTP-запросов, JS-ошибок и горизонтального переполнения. Сценарии выпуска
и проверок просмотрены на скриншотах.

Полный backend 1266/0skip и frontend 621/0skip — предыдущие этапы; приложения,
Dockerfile, миграции и зависимости этим изменением не затронуты. Отдельная Linux
сборка продолжает проверять зафиксированный ранее снимок: новый deploy-скрипт
не является частью её runtime-проверки. Эти два вида доказательств не смешиваются.

## Границы

Окно недоступности теперь включает весь backup; длительность на реальных данных
ещё нужно измерить. Внешние подключения к PostgreSQL или хранилищу не из этого
Compose остаются отдельной проверкой. Совместимость предыдущего образа с новой
схемой, реальное восстановление архива и возврат прежних настроек не доказаны.
Существующие production/development проекты не переключались. Commit/push/deploy
не выполнялись; общий рефакторинг продолжается.
