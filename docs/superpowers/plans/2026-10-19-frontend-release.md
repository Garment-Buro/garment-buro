# Очистка демо-настроек frontend и проверка Linux-образов

Статус: очистка, native-проверки и сборка обоих образов завершены;
полный HTTP через Next остановлен на запуске инфраструктуры.
Общий релиз в работе, production не переключён, commit/push/deploy отсутствуют.

## Изменение

Удалён `frontend/lib/runtime/config.ts`: единственный экспорт
`isMockDataEnabled` не имел импортов/вызовов. Удалены неиспользуемые настройки
`NEXT_PUBLIC_USE_MOCK_DATA` из frontend Dockerfile, server Compose и README.
Отрицательная проверка отсутствия демо-ветки в unfinishedPage сохранена;
исторический аудит сентября остаётся историческим документом.

Данные, providers, стили, шрифты, зависимости, API-контракты и миграции не менялись.
Граф frontend после удаления: 471 TS-файл и 194 компонента import-reachable;
отображение компонентов по-прежнему зависит от условий.

## Подтверждено

Изолированная копия без .env/node_modules/.next: 626 тестов, 0 пропусков,
ESLint без ошибок, production Next build, Chromium проверки аналитики и
кабинета производства прошли за 98 секунд. Child PATH не содержал rtk.
Временная копия, build и executable-каталог удалены. Предупреждения ESLint
об alt в CustomerMediaImage и сборки Alumni Sans SC относятся к прежнему коду.
32 unit-проверки smoke повторно прошли после изменения Compose.
Полные 1299 backend/0skip относятся к предыдущему этапу; backend не менялся.

На Linux-хосте npm и Google Fonts ответили 200; в отдельном ограниченном
Node 24.21.0-контейнере npm, CSS Manrope и файл шрифта также ответили 200.
Контейнер удалён; исходные 14 контейнеров не изменились. Это проверка сети,
она не доказывает доступность из sandbox BuildKit/Turbopack и не объясняет
прежний тайм-аут сборки.

## Контейнерный gate

Отдельный неизменяемый снимок 1547 файлов текущих frontend/backend/deploy
передан на Linux-стенд и сверён по SHA-256. Backend-образ собран для linux/amd64;
frontend прошёл npm ci, но компиляция Next 16.3.8/Turbopack достигла тайм-аута 30 минут.
Архив исключает приватные env, ключи, БД, логи, uploads,
node_modules и .next. Используются текущие Dockerfile, lock и smoke, включая
проверку корзины после restart с остановленным Redis и новый host binding.

Собственный BuildKit ограничен 768 MiB/CPU 1/swap 0: настройки и реальные
cgroup проверены. Он удаляется до runtime.
Изолированный Compose использует свежие volumes, loopback-порты и только
синтетические учётные данные. API/frontend получают отдельные лимиты по
256 MiB; PostgreSQL/Redis/MinIO и setup jobs также ограничены. Конфиги 0600.
Сверяются ID/образ/StartedAt/restart исходных контейнеров и очистка своих ресурсов.
Причина прежнего тайм-аута frontend не считается установленной; успешного
полного Docker/Next результата на момент этого документа ещё нет.

Во время текущей компиляции cgroup почти заполнен: около 805 MB из 768 MiB,
примерно 738 MB anon. Memory pressure full avg10 достигал 25%, some — 45%;
oom/oom_kill оставались 0, CPU-время next-build росло. Это подтверждает давление
на память текущего ограниченного стенда, но не устанавливает причину прежнего
тайм-аута и не является измерением скорости страниц. Эта попытка завершилась
тайм-аутом; своих runtime-контейнеров не запускала. Builder, образ, его cache
volume и приватные конфиги удалены; postflight подтвердил точное совпадение
исходных 14 контейнеров.

Отдельная локальная Linux VM с binfmt-эмуляцией amd64: при builder 2 GiB
frontend получил явную ошибку нехватки памяти, при 4 GiB/2 CPU оба образа
успешно собраны. Затем Compose остановился до HTTP. Независимые pull
подтвердили недоступность MinIO/mc в Docker Hub и Quay, официальный архив
бинарников вернул 410. PostgreSQL и Redis скачались. Это не устанавливает
причину native-тайм-аута и не измеряет скорость страниц. Временная VM удалена.
Полные результаты, границы и официальные источники:
[сборка образов и storage](2026-10-19-container-build-storage.md).

## Аудит frontend-зависимостей 19 октября

Свежий `npm audit --omit=dev --json`: 0 уязвимостей. Полный audit: 5 high
записей в одной цепочке `eslint-config-next → @next/eslint-plugin-next →
fast-glob → micromatch → braces`, один advisory
[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
На момент проверки advisory не указывает исправленную версию braces.
Это остаточная зависимость инструмента lint; отдельный production audit
не содержит её. В текущем eslint.config нет пользовательского next.rootDir;
проверенный helper читает rootDir из настроек ESLint. Это не доказательство
полной неэксплуатируемости development-окружения.

Предложение npm меняет eslint-config-next 16 на 14.2.35 с major downgrade.
Оно не применялось; audit fix/force, ignore и изменения lock отсутствуют.
Наличие исправления нужно перепроверять при следующем обновлении инструментов.

Открыты GitHub Actions для актуального кандидата, совместимость прежнего
образа с новой схемой, настоящий restore/rollback и окно обслуживания.
