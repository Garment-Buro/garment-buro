# Производственные модели, ткани и расход: страницы и полные данные редактора

Этап выполнен локально, без stage/commit/push/deployment. Основной редактор товаров остаётся производство → «Пресеты». Здесь изменены справочники в «Модели и склад»; это отдельный сценарий настройки производственных моделей/материалов, а не второй редактор товаров.

## Что было исправлено

Production GET моделей/тканей фиксировал limit=100 и cursor=None. Браузер фильтровал/сортировал только первые 100 записей. Категории считали модели по этому срезу. Открытие модели брало поля из списка, который не включал base_length_cm/base_width_cm/extra_width_price_per_cm размера; изменение названия могло потерять сохранённую геометрию/надбавку. Неактивные исторические размеры также попадали в форму как обычные размеры.

API ткани возвращает balance.available_meters, а экран читал available_quantity и подставлял ноль. Это давало неверное отображение остатков, фильтры и сортировку. Нормативы расхода дополнительно загружали полный справочник моделей, а названия искали в первых 100 моделях/тканях. Выбранный ID зависел от доступного среза.

## Текущие границы

- `directory_schemas → directory_repository → directory_service`: новый read model в CRM. Production router остаётся адаптером с прежним require_system_admin. Права покупателя, владельца коллекции и менеджера производства не расширены.
- GET `/api/production/admin/assortment/directory/models`: краткие карточки из десяти полей, включая число активных размеров, число товаров и обозначение опубликованной техкарты. Ни sizes, ни description, ни catalog_product_ids в списке нет. Скалярная SQL-проекция, один SELECT и limit+1 без ORM identity map.
- GET `.../models/{id}`: отдельная полная запись для редактирования со всеми сохранёнными полями и версиями. В форме используются только активные размеры; архивные не отправляются обратно как активные. Неизвестный ID даёт 404, ошибка или неполный ответ не открывает пустой редактор. Закрытие отменяет GET; старый ответ не открывает форму заново.
- GET `.../directory/fabrics`: одна SQL-проекция ткани и её баланса в метрах; доступно = on_hand_meters − reserved_meters. Отсутствующий баланс отличается от неверного ответа. Фильтр low сравнивает доступное с minimum_stock_meters, available означает выше минимума; отсутствие баланса считается нулём. Decimal сохраняется на сервере и в cursor.
- GET `.../directory/fabric-requirements`: страницы нормативов с названиями модели и ткани из JOIN. Для подписи не требуется полный справочник. GET `.../directory/selected?kind=models|fabrics&ids=...` возвращает максимум 50 коротких выбранных записей, включая существующие скрытые записи; список выбора и подтверждённый ID независимы.
- GET `.../model-categories` возвращает model_count из SQL для всей категории. Поиск/пагинация моделей не меняют этот счётчик.

Поиск, фильтры и сортировки происходят в SQL. Страница по умолчанию 24, максимум 100. Cursor содержит вид справочника, ожидаемые фильтры и пару значение сортировки+ID. Равные имена, цены и остатки не теряют записи; cursor от другого фильтра/сортировки/справочника отклоняется. %, _ и обратный слеш ищутся буквально; PostgreSQL использует UnicodeLower/pg_c_utf8 и стабильную C-сортировку. Неизвестные query parameters запрещены.

## Frontend и оболочки

`AdminModels → useModelDirectory → usePagedCatalog`: краткие страницы. Полная модель читается только по кнопке редактирования. Ошибка продолжения сохраняет карточки, неправильный cursor предлагает обновление. Выбор новой модели остаётся отдельным явным действием.

`AdminFabrics → useFabricDirectory + useFabricRequirements`: независимые страницы тканей и нормативов. `ReferencePicker` — общий небольшой UI одиночного выбора; у модели и ткани отдельные read adapters. Он не оборачивает экран и не создаёт Provider. Поиск/продолжение не сбрасывают выбранный ID, существующий ID разрешается отдельно сервером. Общая производственная сессия/epoch отменяет устаревшие операции.

Числа в форме не дополняются нулями. Сантиметры сохраняют точность до 0,01 см, расход/минимальный складской остаток — до 0,001 м, как на сервере. Человеческий рост остаётся отдельным полем. Запись ткани явно выбирает разрешённые поля: сохраняет существующую скрытую цену за метр и не отправляет balance/id/version; expected_version передаётся отдельно. Запись модели сохраняет полный корректный набор мерок активных размеров и надбавку. Устаревший expected_version по-прежнему получает 409.

## Удалённые чтения и выпуск

Production GET `/fabrics` и GET `/fabric-requirements` удалены после удаления последних frontend потребителей. POST/PUT по прежним адресам сохранены. Схема БД не менялась; head остаётся 0072. Новые frontend/backend должны выпускаться согласованно: старые массивы и неполные DTO не интерпретируются как правильные новые ответы.

На момент этого этапа production GET `/models` требовался четырём старым экранам: лекалам, техкартам, фурнитуре и упаковке. Для них восстановлены потерянные поля размеров в старом read DTO. Следующим [этапом складских справочников](2026-10-18-stock-directories.md) фурнитура и упаковка перенесены; старое чтение моделей осталось только у лекал и техкарт. Их ограниченные списки и большие формы требуют дальнейшего упрощения.

## Проверки

Полный backend: **1059 passed, 0 skipped**, 297.24s на Python 3.12.12 с отдельными PostgreSQL 17 и настоящим MinIO; временные окружение/данные/конфигурация удалены. Контрактный набор идёт на SQLite и PostgreSQL: 130 моделей, 130 тканей, 130 нормативов; все сортировки и равные значения, буквальный поиск и кириллица на PostgreSQL, реальные резервы/метры, count категории, SQL projection/identity map, cursor scopes, guest/identity-only 401 и production manager 403. Настоящий PUT изменения только названия сохраняет геометрию/надбавку и не активирует архивный размер; старый PUT отклоняется.

Полный frontend: **580 passed, 0 skipped**, lint и production build/TypeScript. Пять новых проверок контрактов, включая отказ старого поля available_quantity и неполной размерной записи. Прежние статические проверки неверно запрещали точность действующего серверного контракта; они обновлены, а сохранение дробных значений проверено исполняемым browser gate.

`check:admin-catalog`: настоящий standalone Next/Chromium с синтетическим HTTP API. По 130 карточек/строк/нормативов; страницы по 24; отсутствие detail prefetch; отказ/повтор детали без пустой формы; failed append, invalid cursor и устаревший поиск; сохранность черновика после отказа PUT; 64,25 × 72,35 см и надбавка 3,25; исключение архивного размера; сохранение 1,234 м и выбранных ID при пустом поиске; 25 м доступного вместо ошибочного нуля, сохранение цены 12,34 ₽/м и минимума 15,123 м. Модели и выбор норматива проверены на 320/390/736/1280 px, включая короткий landscape 736×390. Прежние сценарии кабинетов тоже прошли.

Это доказательство корректности запросов и границ, не нагрузочный замер большого production справочника. Query plans/индексы на большем наборе и реальные устройства остаются проверками общего выпуска. Сохраняются прежние предупреждения CustomerMediaImage alt и Starlette test client. Docker/Actions, публичный сайт, backup/restore/внешние writers, предыдущий образ и реальная оплата не проверялись этим этапом.
