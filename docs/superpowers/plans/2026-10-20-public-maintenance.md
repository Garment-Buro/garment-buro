# Публичное окно обслуживания релиза

20.10.2026 добавлен единый постоянный флаг обслуживания для управляемых
production/development HTTPS vhosts. До остановки API/workers, backup и
миграций release проверяет публичный Nginx, создаёт собственный флаг и требует
503 от всех входных доменов. Обычная ошибка backend не считается подтверждением.
Владение флагом, отдельные среды, блокировка конкурирующих операций и fsync
защищают восстановление; корневой каталог доступен Nginx только на traversal,
каталоги сред и секреты остаются закрытыми.

Внутренние проверки API/Next обходят публичный proxy и проходят при закрытом
трафике. При rollback старая версия должна принять схему, запуститься и пройти
HTTP до открытия. Новая версия фиксируется до первого открытия трафика.
При частичной ошибке открытия сохраняются её образы/metadata и снова закрывается
флаг; автоматический возврат после возможного нового заказа запрещён.

153 профильных теста прошли без пропусков, включая прежние67 release tests,
backup/verifier, управление флагом, rollback installer и новые границы открытия.
В этих тестах Docker, Linux-инструменты и публичный probe подставлены;
настоящий helper управляет файлами/владением и исполняет ошибки восстановления.
На настоящем Nginx1.28.0, собранном только для локальной проверки на Darwin/arm64,
пройдены5 конфигураций из репозитория: trusted HTTPS controller, страницы,
POST API/загрузки, storage/static и новые WebSocket handshakes; заблокированные
запросы не достигли fixture upstream. Restart Nginx сохраняет блокировку;
ошибка второго/третьего origin возвращает её; неправильный общий путь отвергнут
до изменения приложений. Прежняя cutover-блокировка создания заказов в snapshot
сохранена. Privacy gate8 конфигураций/129 событий и два negative controls прошли.
Runtime-исходники приложения не менялись; полный suite1409 относится к прежнему
этапу, новый полный прогон после этих deployment-правок ещё не выполнен.

CI содержит обе проверки Nginx и доставляет helper, но Actions не запускался.
Не выполнен новый настоящий rootless release с этим публичным барьером;
это следующий обязательный gate перед утверждением cutover. Рабочие БД/S3,
серверная конфигурация и публичный сайт не менялись; commit/push/deploy не было.
Режим обслуживания закрывает новые публичные запросы. Прямые writers,
выданные ранее соединения и внешние провайдеры требуют отдельной координации.
Нельзя обещать нулевую потерю данных при возврате к более раннему checkpoint.
Инструкция установки/восстановления — в deploy/README.md.
