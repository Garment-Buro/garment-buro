# Удаление старого admin-адаптера и реальный запуск backend

Статус: настоящий Linux backend и полный native-набор прошли. Production
не переключён; commit/push/deploy отсутствуют. Общий релиз продолжается.

## Изменения

Основной редактор остаётся в производстве → «Пресеты». Frontend-маршрут
`/admin/models` перенаправляет на `/production?section=presets`.
Удалён `backend/app/api/legacy_admin.py` и его подключение в factory: этот
адаптер только регистрировал старые `/admin` и `/admin/{path:path}` ради 404.
Обычное отсутствие маршрута даёт тот же результат без лишнего модуля.
Современные `/api/production/admin/*` сохраняются.

Регистрация проверена отдельно от HTTP. 8 методов × 4 прежних адреса дают 404.
До удаления адаптера новый тест отсутствия регистрации был красным.

В smoke исправлена проверка постоянной корзины. Настоящий `docker compose
start backend` на изолированной паре сервисов поднял Redis через `depends_on`.
Поэтому успешное чтение после такой команды не доказывало работу без Redis.
Теперь используется `up -d --no-deps --no-recreate --pull never --wait`;
дополнительный `ps --status running --services redis` запрещает успех при
работающем Redis. В той же паре контейнеров новая команда оставила Redis exited.
Контейнеры диагностики удалены. [Опции Compose start](https://docs.docker.com/reference/cli/docker/compose/start/).

Четыре новых случая проверяют перезапуск API без Redis с двумя разными HTTP-
границами и с общей границей, неожиданно работающий Redis и потерю корзины.
Регрессии воспроизведены красными до исправления.
32 smoke unit прошли, Ruff и format четырёх Python-файлов прошли.

Также исправлено чтение случайного локального порта после перезапуска.
Реальный Docker в изолированной паре контейнеров сменил binding
`127.0.0.1:32775` → `127.0.0.1:32776`; старый адрес не принимал соединение,
новый принимал, Redis оставался exited. Теперь endpoint API определяется
повторно через Compose. Адрес отдельного frontend сохраняется; backend-only
проверка с общей HTTP-границей получает новый адрес для обоих чтений.

## Проверки и границы

После удаления admin-адаптера полный строгий native-набор прошёл:
1295 тестов без пропусков, Python 3.12.12, свежие PostgreSQL 17/MinIO,
484 секунды с подготовкой. Собственные процессы, БД, объекты и конфиг удалены.
После первого исправления smoke прошли 1298/0skip за 488 секунд с подготовкой.
После исправления binding полный строгий набор прошёл: 1299/0skip за 487 секунд
с подготовкой, свежие PostgreSQL 17/MinIO. Собственные процессы, БД, объекты и
приватный конфиг удалены. Четыре новых случая входят в этот полный результат.
Frontend не менялся: 626 тестов, production Next build и Chromium относятся
к предыдущему этапу истории клиента и здесь не повторяются.

Первая Linux-попытка этого этапа: все 736 файлов backend/deploy совпали по
SHA-256; образ linux/amd64 собран из текущего Dockerfile/lock. Настоящие init
роли БД, MinIO и Alembic прошли. API запустился uid 10001: readiness с реальными
PostgreSQL/MinIO, пустые каталоги, закрытые ответы 401/no-store и старые 404
прошли. Сценарий корзины дошёл до `Compose start`, который завершился exit 1.
Первоначальная причина этого exit не сохранена; отдельная диагностика доказала
неверную семантику команды для требования «без Redis». Результат после
перезапуска в этой попытке не заявляется.

Вторая попытка прошла init/миграции и начальные HTTP-проверки, затем остановилась
с URLError при проверке перезапуска. После этого отдельно воспроизведена смена
порта; успешное выполнение полного сценария в этой попытке не заявляется.

Третья попытка прошла полностью за 353 секунды: linux/amd64, все 736 файлов
backend/deploy совпали по SHA-256. Пустые публичные списки, 401/no-store,
старые 404 и readiness PostgreSQL/MinIO прошли. Настоящий товар 1500 ₽ и
переданная клиентом цена 0.01 дали серверные 1580 ₽ с надбавкой 80 ₽,
количеством 2 и customization. Replay сохранил снимок, старая ревизия дала 409.
После stop API/Redis запущен только API; по новому binding прочитан тот же
снимок. Состояние Redis дополнительно проверено через inspect: exited.
Alembic upgrade head повторно прошёл после записи корзины.

Собственные контейнеры/тома/сети, builder и тег образа третьей попытки удалены;
конфиг удалён. После копирования отчётов отдельно проверены отсутствие
собственных ресурсов и неизменность исходных 14 контейнеров; временная папка
на сервере удалена.

Собственные ресурсы первых двух попыток удалены. 14 исходных контейнеров совпали по
ID, image ID, StartedAt и RestartCount; приватный конфиг и удалённая папка
удалены. Финальный запуск использовал отдельный неизменяемый снимок с исправленным
smoke, собственный builder 768 MiB/CPU 1/swap 0 и отдельные volumes/loopback-порты.
Только синтетические учётные данные; capability корзины остаётся в памяти/HTTP.

Этот этап проверяет backend напрямую. Linux frontend, HTTP через Next,
GitHub Actions, старый образ с новой схемой, реальный restore/rollback и
производственное окно обслуживания остаются отдельными воротами выпуска.
Прежний тайм-аут frontend при 768 MiB/CPU 0,5 не считается успешной сборкой.
Новых providers, зависимостей и миграций на этом этапе нет.
