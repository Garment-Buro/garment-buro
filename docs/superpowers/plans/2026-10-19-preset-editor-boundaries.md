# Границы редактора пресета

Статус: этап выполнен локально; общий рефакторинг релиза продолжается. Основной интерфейс товаров — производство → «Пресеты», согласно решению пользователя. Backend, бизнес-формула принтов и Providers на этом этапе не менялись.

## Проблема и результат

TypeScript-тип ответа не проверял настоящий JSON. Отсутствующее поле, включая nullable-ссылку на галерею или таблицу размеров, могло незаметно попасть в черновик как undefined и исчезнуть из полного PUT. Upload принимал любую непустую строку URL без подтверждённого ID. Большая форма смешивала карточку, поиск моделей, медиа, матрицу вариантов и управление запросами.

`lib/products/editorReads.ts` проверяет весь используемый редактором detail до установки черновика: запрошенный ID, версию, строки/null, числовые значения, исходные и вычисленные остатки, массив тегов, все медиа-поля, уникальные ID вариантов и ссылки на справочники. Нет восстановления отсутствующих данных значениями по умолчанию. Неполный/чужой/повреждённый ответ показывает ошибку и повтор загрузки. Модель и её размеры, страницы моделей/тканей и точный набор выбранных тканей также проходят проверку.

Upload требует положительный целочисленный media ID и постоянный URL: абсолютный http(s) либо относительный от корня. Временные blob/data, protocol-relative ссылки, credentials, пробелы, обратные слеши и запятая-разделитель CSV отклоняются. Проверенная строка сохраняется буквально, включая percent encoding; отдельного искусственного списка CDN-доменов нет. Ошибка не стирает прежнюю картинку, input сбрасывается для повторного выбора.

## Состав формы и оболочки

`ProductionTerminal → workspace с ключом сессии → AdminAssortment → AdminProducts → ProductEditorDialog`.

- `ProductEditorDialog` — рамка загрузки/ошибки/конфликта и действия, 133 строки. Использует визуальный `AssortmentDialog` и один `useCatalogProductEditor`.
- `PresetIdentityFields` — название, slug, источник, теги, независимый выбор категории и модели, цены, описание, состав, активность и упаковка.
- `PresetMediaFields` — основные изображения и дополнительные галереи; получает batch-upload от контроллера.
- `PresetVariantFields` — размеры, постраничный поиск тканей, сохранённые выбранные ссылки, матрица до 200 вариантов и дочерние поля одного варианта.
- `presetFields.ts` — только общий тип props и функциональное изменение одного поля черновика.

Это дочерние блоки, не Provider. Новых контекстов и бизнес-хранилищ в localStorage нет. Поиск моделей/тканей монтируется вместе с проверенной формой; невалидный первоначальный detail не вызывает предварительные запросы этих справочников. Текущие upload/save locks, expected_version, явная замена черновика при конфликте и защита от устаревших ответов сохранены.

## Проверка

- 614 frontend-тестов, 0 ошибок/пропусков. Новые проверки удаляют по очереди каждое обязательное поле detail/варианта, проверяют неверные типы/ID/версии, дубликаты, лимит, nullable-медиа, страницы/курсоры, неполные выбранные ткани и upload receipts. HTTP 200 тоже обязан пройти decoder.
- TypeScript, production build и ESLint прошли; осталась прежняя alt-text warning в `CustomerMediaImage.tsx`. Build использует флаги identity session, catalog writes и CRM cabinet. Это локальная сборка.
- Полный gate standalone Next/Chromium прошёл с синтетическим HTTP backend. Новые сценарии: четыре повреждённых detail без формы/предзагрузки, отказ и повтор страниц справочников без потери выбранного ID, неподтверждённый upload, batch из двух файлов, два submit → один PUT, сохранность скрытых видео/таблиц/сырого stock, 503, 409, отказ перечитывания и возврат к прежнему черновику. Ширины 320/390/736/1280; просмотрен снимок 390 px.
- Backend не менялся и здесь повторно не запускался. Предыдущий этап независимо прошёл 1095 backend-тестов без пропусков на собственных PostgreSQL17/MinIO; браузерный fixture не заменяет это доказательство.

Локальные журналы: `preset-fields-frontend-final.log`, `preset-fields-lint.log`, `preset-fields-build.log`, `preset-fields-browser-final.log` в каталоге визуализации текущего чата. Карта пересчитана по 468 TS-файлам и 194 компонентам: все import-reachable, что не доказывает видимость при любых runtime-флагах.

## Оставшиеся ограничения

Frontend отказывается редактировать source с более чем 200 вариантами; это не ограничение объёма серверного SELECT. Detail модели ещё читает исторические размеры целиком, а options выбирают полные ORM-родители. Ограничение source/history и оставшиеся canonical CRM reads требуют следующего этапа. Подстрочные/агрегатные SQL планы и общие ворота выпуска также остаются в работе. Docker/Actions, production, реальный телефон и реальная оплата этим локальным этапом не подтверждены. Commit/push/deploy не выполнялись.
