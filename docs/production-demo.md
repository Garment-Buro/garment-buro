# Учебный производственный терминал

## Назначение

Операторская команда `python -m scripts.seed_production_demo --confirm-demo`
создаёт десять отдельных учебных сотрудников и десять заказов, по одному на участок.
Коды случайные, шестизначные, с префиксом категории. Коды и идентификаторы сотрудников
сохраняются только в приватном JSON, указанном через `--credentials-file`.
В репозиторий, CI и stdout коды не выводятся. Код владельца/администратора не меняется.

Дополнительный обязательный параметр `--reference-image` задаёт PNG/JPEG/WebP для
проверки загрузки приватных файлов. Это учебное фото, **не настоящее лекало или
печатный оригинал**: соответствующее предупреждение есть в именах файлов,
спецификациях и интерфейсе. Изображения изделия используют существующие ассеты худи.

## Безопасность

- `orders.is_demo` и `crm_order_projects.is_demo` явно маркируют учебные данные.
- Учебные заказы имеют нулевую стоимость и не имеют записей Payment, PaymentAttempt,
  FulfillmentJob, OrderWorkflow или CdekShipment. Они не имитируют реальные оплаты.
- Для реальных CRM-проектов обязательная связь с оплатой сохранена ограничением БД.
- Учебные аккаунты отмечены в `production_demo_employees`. Даже технолог такого
  аккаунта не может читать/изменять реальные проекты, сканировать их или скачивать файлы.
- Платёжный сервис, fulfillment и обработчик СДЭК явно исключают учебные заказы.
- Учебная отгрузка принимает только трек `DEMO-…`, записывает локальную историю,
  но не обращается к перевозчику.
- Финансовая статистика администратора исключает учебные заказы; в списке заказов
  они видны с получателем `ТЕСТ` и признаком `is_demo`.
- Старый CRM API для оплаченных заказов не включает учебные проекты;
  они открываются в производственном терминале.
- Выпуск не запускает подготовку автоматически. Нужна отдельная явная команда
  оператора после резервного копирования и проверки миграции.

## Повторный запуск

Не сбрасывает завершённые учебные сценарии и не меняет существующие коды. Прерванная
подготовка продолжает сохранённую последовательность через идемпотентные команды.
При утраченном файле действующих кодов или отозванном доступе команда останавливается,
а не создаёт новый доступ без ведома оператора. Параллельные запуски на PostgreSQL
блокируются advisory lock. Приватный файл необходимо хранить вне Git с правами `0600`.

## Экраны

`/production` — вход сотрудника, `/production/floor` — рабочие участки,
`/production/admin` — администратор. На мобильном шапка занимает две строки:
аватар/имя/выход сверху, роль и переход администратора снизу. Длинное имя или почта
сокращаются многоточием; полный текст остаётся в DOM и `title`.

Перед реальным запуском производства учебные аккаунты следует отозвать по их ID
через `scripts.production_code --user-id ... --revoke`. Массовое удаление заказов
команда намеренно не выполняет: история прохождения этапов остаётся доступной.
