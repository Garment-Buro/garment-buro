# Выплаты партнёрам через Точку

Проверено по backend и официальной документации Точки 9 сентября 2026 года.

## Текущий сценарий: с ручным подтверждением

1. Партнёр сохраняет реквизиты и запрашивает вывод доступного вознаграждения. Система учитывает уже зарезервированные заявки, чтобы нельзя было вывести одну сумму дважды.
2. Администратор проверяет заявку, получателя и договорные основания и одобряет её. Одобрение само по себе деньги не отправляет.
3. Администратор отдельным запросом создаёт банковскую платёжку для одобренной заявки. Назначение платежа задаётся явно; backend не придумывает условия договора или формулировку НДС.
4. Backend сохраняет операцию до обращения к банку и вызывает `Create Payment For Sign`. Платёж переходит в ожидание подписи. Ссылка подписания доступна администратору, не партнёру.
5. Человек с правом подписи проверяет платёжку в интернет-банке Точки и подписывает её. В этой интеграции нет автоматического подписания или автоматического списания только по нажатию партнёром «Вывести».
6. После включения интеграции worker опрашивает статус банка. `Created` означает обработку, не успешную выплату. Только `Paid` переводит выплату в оплаченные. `Rejected` и `Canceled` учитываются отдельно.

Источники: [Create Payment For Sign](https://developers.tochka.com/docs/tochka-api/api/create-payment-for-sign-payment-v-1-0-for-sign-post), [Платёжные поручения](https://developers.tochka.com/docs/tochka-api/opisanie-metodov/platezhi).

## Ошибки и ручная сверка

Банковская операция связана с одной заявкой. Повтор того же административного действия возвращает существующую операцию; изменить параметры незаметно нельзя. Если после отправки неизвестно, принял ли банк запрос, состояние `unknown` удерживает резерв. Система не повторяет создание платежа вслепую и не переводит сумму повторно. При отсутствии банковского ID нужна ручная сверка в банке.

Не редактируйте сформированную API платёжку в интернет-банке без последующей сверки: по документации Точки после ручного редактирования `Get Payment Status` может оставаться в `Created`, и автоматическое завершение по нему ненадёжно.

## Что сейчас включено

Предоставленный JWT сохранён в `/srv/garment-buro/production/.env` на сервере, права `0600`. Сам токен не включён в этот документ или Git. Сохранение не перезапускает сервисы и не включает выплаты. Проверка чтения счетов ранее вернула HTTP 200 и три счёта, но она не подтверждает права создания платёжек.

Для запуска ещё необходимо выбрать счёт списания из доступных счетов, проверить права токена на нужный банковский метод, подтвердить назначение платежа/договорные формулировки, включить production-настройки интеграции и провести согласованную контрольную выплату. Счёт списания нельзя выбирать автоматически только потому, что он первым пришёл из API. Данный этап не создаёт реальную платёжку и не переводит деньги.
